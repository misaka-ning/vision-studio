# Vision Studio UI 设计

## 产品定位

Vision Studio 面向需要验证、演示和运行本地 ONNX / PyTorch 视觉模型的开发者与研究人员。界面围绕「选择模型 → 选择输入 → 运行 → 检查 → 导出」组织，把图像结果作为工作区的视觉中心。

## 信息架构

- **检测工作台**：常用模型参数、输入队列、画布与目标表集中展示，完成一次推理不需要在多个页面之间切换。
- **模型库**：管理可选模型，明确当前模型与任务，降低误用不同输出格式的概率。
- **模型显示**：以结构图、层级树和参数表检查全局模型，共用模型库中的选择与解析缓存。
- **运行记录**：按运行摘要追溯处理来源与性能，详细结果由导出文件保留。
- **使用指南**：在应用内提供模型格式与操作入口，降低首次使用成本。
- **录制视频**：浏览、播放和导出已完成的本地标注录像。
- **更多**：放在导航末尾，集中运行示例与手动导出结果。

七页顺序固定为检测工作台、模型库、模型显示、运行记录、使用指南、录制视频、更多。模型库是唯一模型选择入口，选择模型后同时用于工作台检测和模型显示；模型库可前往这两个页面，导航只切换页面。

## 视觉语言

2.0 参考 [Fluent-Qt v1.9.2](https://github.com/calvinhxx/Fluent-Qt/tree/v1.9.2) 的暗色 Fluent / WinUI 视觉规范，固定参考提交 `6dfe61e01dff88aa0669b19e7b4faa2d5400e30e`。采用中性灰分层（窗口 `#202020`、卡片 `#272727`、控件 `#303030`），蓝青色 `#60CDFF` 表达主要操作与焦点；主要文字 `#F5F5F5`、辅助文字 `#B8B8B8`，错误与录制仍使用红色。控件圆角 4px、卡片 8px，标题 28px / 600 字重，导航提供 3px 强调条。中文继续使用现有 Noto Sans CJK SC 和 Qt 替代字体。

输入源四个入口移到工作台上方的横向命令栏，输入信息靠近其操作；左栏保留计算设备、颜色／左右目、模型及参数，中间为画布与队列，右栏保留目标表。卡片、表格、下拉弹层、菜单、滚动条、空状态及三种模型展示统一暗色层级，提高辅助文字与焦点的可见性。

仅借鉴上游视觉规范；应用继续使用原 `QPushButton`、`QComboBox`、`QSpinBox`、列表／表格、图标和事件连接，没有引入上游自定义控件、字体、图标或 Gallery 运行栈。上游自有代码采用 MIT，原始许可与固定来源保存在 `packaging/licenses/fluent-qt-design-reference/`；这些材料用于记录设计参考，应用不链接 FluentQt 库，也不新增运行依赖。主题集中在 `assets/fluent-dark.qss`，原生键盘、模型选择、解析缓存、推理、取消、灰度、左右目、录制、导出与文件格式沿用 1.6。

模型显示的图、层级树、参数表、搜索结果和详情沿用这一深色语言。嵌套对象与张量内容也使用明确的背景和文字颜色，避免第三方页面局部白底与浅色字组合而无法阅读。

工作台以「开始检测」作为主操作，运行时提供停止与录像控制；运行示例和手动导出集中在「更多」，状态与快捷键仍保持联动。模型信息与输入来源始终可见。置信度、耗时、类别与图像尺寸以简洁指标展示，目标列表用于精确核对。

图标由 Qt 绘图与矢量资源提供，适应本机显示缩放。中文界面优先使用 Noto Sans CJK SC，并由 Qt 字体系统提供替代字体。

## 交互与状态

空状态解释需要导入什么，并提供内置真实模型示例，让用户在准备自己的模型前就能理解结果展示。运行时显示进度与工作状态，涉及当前任务的设置会锁定，避免中途修改配置造成歧义。

输入尺寸、置信度和 NMS IoU 控件禁用滚轮改值，以明确输入和步进操作调整参数。自动保存每张图片的选项下方提供「打开保存文件夹」入口；模型库可拖动排序并持久保存，重排保持当前全局模型。图片结果按后台保存完成节奏交付，缓存、标注绘制、自动导出和历史写入不占用界面线程；停止唤醒结果交付等待，不等待写入，已交付结果保留供回看。已接受写入完成后再允许新任务；关闭窗口异步等待收尾。CPU OpenCV 当前 forward 不能强制中断，CUDA／PT 保留各自取消机制。

成功后直接更新画布、目标表与指标。运行失败显示可读错误，不用虚构预测替代失败结果。无目标结果与执行失败分开表达。导出结果保存到用户选择的目录。

画布使用原图坐标保存预测，缩放仅影响查看效果。检测框、标签和选择高亮叠加于图像。导出使用原图尺寸绘制检测框与标签，并保留预测坐标。

1.5.0 的输入设置支持 RGB、BGR 与灰度。模型的实际输入通道数从模型读取，灰度只展示统一均值的含义；推理结果和预览显示实际灰度，切回彩色恢复原色并清除旧预测，避免跨颜色模式复用检测。旧版默认彩色设置继续兼容。

视频与摄像头提供完整画面、左目和右目选择，适配单设备水平左右拼接流。所选眼成为当前预览和结果坐标空间，原始拼接帧尺寸用于追溯；图片队列始终使用完整图片。运行期间画面选择与模型预处理设置随任务锁定。

录制按钮在视频或摄像头推理期间可用，以「开始录制 → 结束录制 → 正在保存…」表达生命周期。录像页展示已完成文件，支持选择、播放、暂停和导出；录制与工作台预览刷新分开处理，避免丢掉只因界面节流而未显示的推理帧。「更多」始终位于导航最后。

模型显示由「模型库选用 → 启动本机服务 → 解析模型 → 排列节点 → 就绪」组织状态。HTTP 页面打开后仍等待真正的模型解析和图布局，失败时显示中文说明与重试按钮。格式不识别、文件损坏和没有可显示结构均提供可读反馈；不会以空白浏览器作为成功结果。

模型选择后在后台异步预加载结构，完成后保留已解析页面缓存；进入模型显示不重复启动加载。未完成时保留当前加载状态。「结构图」「层级树」「参数表」是同一模型的三种展示方式，切换模式复用解析结果；搜索与详情用于检查当前信息，不产生新的推理任务。ONNX 图表达运算节点与连接，普通 PT 的树和分组表达可读取的模块包含关系与权重信息，不推断不存在的 forward 关系。错误状态提供重试入口。任何非 ONNX 文件均显示独立的一行提示：

想看完整结构，建使用导出的 ONNX。

结构图保留 Netron 原生查找；Qt 搜索框用于层级树与参数表。树过滤保留匹配项的祖先，表过滤覆盖参数路径、类型、形状、元素数和备注。选择条目显示可靠元数据，超出显示限额时提示截断。选择新模型会清除旧搜索、详情与缓存，同时保留当前模式，避免把不同模型的结果混在一起。

## 实现边界

桌面框架使用原生 Qt Widgets 与 C++；模型显示页通过 Qt WebEngine 内嵌 Netron 9.3.1。ONNX forward 在 C++ 工作线程执行；`.pt` 使用独立的本地 Python / PyTorch 进程，Qt 工作线程管理请求并复用模型。结果通过 Qt signals / slots 更新主线程界面。UI 设计保留标准文件对话框、窗口控制和键盘行为，以便在桌面环境中使用。

Netron 的页面及模型由随包 Python 环境在回环地址随机端口提供，文件留在本机，页面不访问远程服务。模型显示仅解析静态文件，不执行 `torch.load`；`.pt` 中的权重或模块信息可能无法组成完整运算图，建议导出 ONNX 后查看。正式 DEB 携带浏览器辅助进程、资源和语言文件，无需另装浏览器或在线下载页面。

模型导入同时接受 `.onnx` 和 `.pt`，明确显示对应后端。`.pt` 自动读取模型任务与类别名称；ONNX 显示需要用户匹配的输出格式、标签与预处理参数。分类视图显示 top-1 标签及 top-5 列表，检测视图显示原图坐标框。

本版提供单任务推理工作台，沿用 1.6 的 NVIDIA GPU 与 CPU 后端。2.0 正式版在 Fluent 界面与批量回看基线上改进参数防误改、停止响应、保存目录入口和模型库排序；项目协作、训练、数据集标注、分割与姿态不属于本版范围。
