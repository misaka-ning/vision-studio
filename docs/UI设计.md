# Vision Studio UI 设计

## 产品定位

Vision Studio 面向需要验证、演示和运行本地 ONNX / PyTorch 视觉模型的开发者与研究人员。界面围绕「选择模型 → 选择输入 → 运行 → 检查 → 导出」组织，把图像结果作为工作区的视觉中心。

## 信息架构

- **检测工作台**：包含各自占用完整工作区的「图像预览」「评估与阈值」两个子页。前者集中展示参数、画布、队列与目标表，后者集中显示指标、曲线、阈值、错例和报告；全局模型、数据集与范围共用，切页只改变查看位置。
- **模型库**：管理可选模型，明确当前模型与任务，降低误用不同输出格式的概率。
- **模型显示**：以结构图、层级树和参数表检查全局模型，共用模型库中的选择与解析缓存。
- **运行记录**：按运行摘要追溯处理来源与性能，详细结果由导出文件保留。
- **使用指南**：在应用内提供模型格式与操作入口，降低首次使用成本。
- **录制视频**：浏览、播放和导出已完成的本地标注录像。
- **模型转换**：按全局模型设置目标格式与输出位置，在后台执行并检查完成状态。
- **更多**：放在导航末尾，集中 GPU 环境检查与手动导出结果；公开示例入口自 2.4.0 退出。

八页顺序固定为检测工作台、模型库、模型显示、运行记录、使用指南、录制视频、模型转换、更多。模型库是全局模型选择入口，工作台、模型显示和转换页默认来源共用选择；转换页返回同一模型库选用模型，导航只切换页面。

## 视觉语言

2.0 参考 [Fluent-Qt v1.9.2](https://github.com/calvinhxx/Fluent-Qt/tree/v1.9.2) 的暗色 Fluent / WinUI 视觉规范，固定参考提交 `6dfe61e01dff88aa0669b19e7b4faa2d5400e30e`。采用中性灰分层（窗口 `#202020`、卡片 `#272727`、控件 `#303030`），蓝青色 `#60CDFF` 表达主要操作与焦点；主要文字 `#F5F5F5`、辅助文字 `#B8B8B8`，错误与录制仍使用红色。控件圆角 4px、卡片 8px，标题 28px / 600 字重，导航提供 3px 强调条。中文继续使用现有 Noto Sans CJK SC 和 Qt 替代字体。

工作台公开输入集中为 YOLO 数据集、视频和摄像头，输入源与推理设备位于上方紧凑任务条，数据集摘要、集合操作与校验状态保留一行。检测子页左侧提供模型、颜色／左右目和推理参数，中间为画布与队列，右侧为目标表；评估子页使用完整宽度展示分析内容。文件夹与 YAML 使用同一个深色选择器；数据集设置为锚定按钮的独立悬浮卡片，不占父布局，不挤压画布。卡片、表格、下拉弹层、菜单、滚动条、空状态及三种模型展示统一暗色层级，提高辅助文字与焦点的可见性。

仅借鉴上游视觉规范；应用继续使用原 `QPushButton`、`QComboBox`、`QSpinBox`、列表／表格、图标和事件连接，没有引入上游自定义控件、字体、图标或 Gallery 运行栈。上游自有代码采用 MIT，原始许可与固定来源保存在 `packaging/licenses/fluent-qt-design-reference/`；这些材料用于记录设计参考，应用不链接 FluentQt 库，视觉参考本身不新增运行依赖。主题集中在 `assets/fluent-dark.qss`，推理、灰度、左右目、录制和结果格式保留现有约定；2.1 新增模型管理交互及转换页。

模型显示的图、层级树、参数表、搜索结果和详情沿用这一深色语言。嵌套对象与张量内容也使用明确的背景和文字颜色，避免第三方页面局部白底与浅色字组合而无法阅读。

检测子页以「开始检测」作为主操作，评估子页提供明确的「开始评估」，运行时提供对应停止控制；录像面向视频／摄像头，手动导出集中在「更多」，状态与快捷键保持联动。只切页不修改任务模式、阈值、范围或缓存，不自动推理；显式采用报告配置仍是独立操作。模型信息与输入来源始终可见。置信度、耗时、类别与图像尺寸以简洁指标展示，目标列表用于精确核对。

图标由 Qt 绘图与矢量资源提供，适应本机显示缩放。中文界面优先使用 Noto Sans CJK SC，并由 Qt 字体系统提供替代字体。

2.7.1 的界面修复范围是 `QComboBox` 弹出列表顶部与底部的浅色条：列表、容器和滚动辅助区域应保持同一深色层级，选中、高亮、禁用及文字对比应清晰。实际 Qt 弹窗须在短列表、长列表及上下边界检查，不能只凭主窗口样式字符串认定显示正确；选择、键盘与滚动逻辑不作变更。

## 交互与状态

空状态说明受支持的数据集、视频与摄像头入口，启动不自动加载示例图片。运行时显示进度与工作状态，涉及当前任务的设置会锁定，避免中途修改配置造成歧义。

输入尺寸、置信度和 NMS IoU 控件禁用滚轮改值，以明确输入和步进操作调整参数。自动保存每张图片的选项下方提供「打开保存文件夹」入口；模型库可拖动排序并持久保存，重排保持当前全局模型。图片结果按后台保存完成节奏交付，缓存、标注绘制、自动导出和历史写入不占用界面线程；停止唤醒结果交付等待，不等待写入，已交付结果保留供回看。已接受写入完成后再允许新任务；关闭窗口异步等待收尾。CPU OpenCV 当前 forward 不能强制中断，CUDA／PT 保留各自取消机制。

模型右键菜单作用于指针下的条目，右键本身不改变全局选择。名称和备注持久保存，条目持续显示真实路径；重命名对话框明确只改显示名称，移除后提示原始文件保留。

转换页按「来源模型 → 导出设置 → 执行与结果」组织三张暗色卡片，持续展示名称与真实路径。目标格式、尺寸、ONNX Opset、输出目录与文件名称集中设置；运行开始后固定本次输入。主操作为「开始转换」，后台显示进度、阶段日志和「取消转换」，成功后提供打开目录与加入模型库。取消、失败、不支持来源和已有输出都有文字反馈；若取消请求晚于完整输出提交，明确提示完成或保留文件。成功不自动替换全局模型，用户明确加入库后才选用结果并应用对应元数据。

大队列在 GUI 事件循环中分片建立，缩略图按可见范围后台读取；原图、预处理预览与缓存叠加异步构建，显示前核对当前选择与配置代次。快速选图、切换颜色或清空来源后拒绝旧回调，避免串帧；后台读取不重新运行模型。实际心跳和加载耗时以同版测试环境的原始证据为准。

悬浮设置支持再次点击、外部点击、Esc 和关闭按钮；窗口调整或切页时收起，运行时锁定编辑。折叠时保留可发现的校验状态，点击可读完整原因，长错误支持滚动和复制。卡片展开前后工作台工具栏与画布几何保持不变。

成功后更新画布、目标表与指标。运行失败显示可读错误，不用虚构预测替代失败结果。无目标结果与执行失败分开表达。导出结果保存到用户选择的目录。

画布使用原图坐标保存预测，缩放仅影响查看效果。检测框、标签和选择高亮叠加于图像。导出使用原图尺寸绘制检测框与标签，并保留预测坐标。

1.5.0 的输入设置支持 RGB、BGR 与灰度。模型的实际输入通道数从模型读取，灰度只展示统一均值的含义；推理结果和预览显示实际灰度，切回彩色恢复原色并清除旧预测，避免跨颜色模式复用检测。旧版默认彩色设置继续兼容。

视频与摄像头提供完整画面、左目和右目选择，适配单设备水平左右拼接流。所选眼成为当前预览和结果坐标空间，原始拼接帧尺寸用于追溯；图片队列始终使用完整图片。运行期间画面选择与模型预处理设置随任务锁定。

录制按钮在视频或摄像头推理期间可用，以「开始录制 → 结束录制 → 正在保存…」表达生命周期。录像页展示已完成文件，支持选择、播放、暂停和导出；录制与工作台预览刷新分开处理，避免丢掉只因界面节流而未显示的推理帧。「更多」始终位于导航最后。

模型显示由「模型库选用 → 启动本机服务 → 解析模型 → 排列节点 → 就绪」组织状态。HTTP 页面打开后仍等待真正的模型解析和图布局，失败时显示中文说明与重试按钮。格式不识别、文件损坏和没有可显示结构均提供可读反馈；不会以空白浏览器作为成功结果。

模型选择后在后台异步预加载结构，完成后保留已解析页面缓存；进入模型显示不重复启动加载。未完成时保留当前加载状态。「结构图」「层级树」「参数表」是同一模型的三种展示方式，切换模式复用解析结果；搜索与详情用于检查当前信息，不产生新的推理任务。ONNX 图表达运算节点与连接，普通 PT 的树和分组表达可读取的模块包含关系与权重信息，不推断不存在的 forward 关系。错误状态提供重试入口。任何非 ONNX 文件均显示独立的一行提示：

想看完整结构，建使用导出的 ONNX。

结构图保留 Netron 原生查找；Qt 搜索框用于层级树与参数表。树过滤保留匹配项的祖先，表过滤覆盖参数路径、类型、形状、元素数和备注。选择条目显示可靠元数据，超出显示限额时提示截断。选择新模型会清除旧搜索、详情与缓存，同时保留当前模式，避免把不同模型的结果混在一起。

## 实现边界

桌面框架使用原生 Qt Widgets 与 C++；模型显示页通过 Qt WebEngine 内嵌 Netron 9.3.1。ONNX forward 在 C++ 工作线程执行；`.pt` 使用独立的本地 Python / PyTorch 进程，Qt 工作线程管理请求并复用模型。结果通过 Qt signals / slots 更新主线程界面。UI 设计保留标准文件对话框、窗口控制和键盘行为，以便在桌面环境中使用。

Netron 的页面及模型由随包 Python 环境在回环地址随机端口提供，文件留在本机，页面不访问远程服务。模型显示仅解析静态文件，不执行 `torch.load`；`.pt` 中的权重或模块信息可能无法组成完整运算图，建议导出 ONNX 后查看。正式 DEB 携带浏览器辅助进程、资源和语言文件，无需另装浏览器或在线下载页面。

模型导入接受 `.onnx`、`.pt` 和 `.torchscript`，明确显示对应后端。兼容 PT／TorchScript 读取模型任务与类别名称；通过转换页加入库的结果应用已记录的任务、类别、尺寸和通道，其余 ONNX 仍需用户匹配输出格式、标签与预处理参数。分类视图显示 top-1 标签及 top-5 列表，检测视图显示原图坐标框。

本版保留 NVIDIA GPU／CPU 后端、2.0 的参数防误改、停止响应、保存目录与排序。2.1.0 新增模型库右键管理与 PT → ONNX／TorchScript 转换，转换使用后台 CPU Python 进程，输出加入库后由既有后端执行。项目协作、训练、数据集标注、ONNX 还原训练检查点、分割与姿态不属于本版范围。

## 2.8.0：代码视图与启动偏好

YOLO YAML 采用 One Dark Pro 风格的原生只读代码区，行号与正文独立滚动绘制，当前行和搜索命中分别可辨。仅实际可恢复架构的 PT 显示入口，ONNX 与不支持模型隐藏；加载或换模拒绝旧内容与过期回调，继续共用全局缓存。

侧栏把「使用指南」放在「更多」正上方，视觉顺序与键盘 Tab 顺序一致，各页目标保持。指南按模型、输入、检测、评估、错例、导出、可视化、转换和环境组织，避免过时入口与重复章节。更多页的启动卡片提供默认开启的恢复开关，解释关闭保留记录、下次应用启动生效、不自动推理；它不配置系统开机自启动。
