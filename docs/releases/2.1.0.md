## 模型管理与转换

模型右键提供打开位置、添加／修改备注、重命名显示名称与从列表移除。菜单作用于点击条目，右键本身不改变全局选择；名称与备注持久保存，留空恢复名称或清除备注。重命名不改磁盘文件名、路径、类别或权重，移除保留原始文件。移除当前项时选择仍存在的模型，无可用项时清空选择，拖动排序规则保留。

新增「模型转换」位于「录制视频」之后、「更多」之前，默认使用模型库全局模型，开始后固定本次来源。兼容的现代 Ultralytics 检测／分类、旧版 YOLOv5 检测完整 PT 及带必要元数据的标准 TorchScript 可导出 ONNX／TorchScript；CPU FP32、batch=1、固定正方形、原始检测输出不含 NMS，读取 C1／C3，输入尺寸为 32 的倍数，ONNX 提供 Opset 12／17。任务、类别、形状与通道元数据保留，TorchScript 保存 `config.txt`。

后台进度、阶段日志与取消不阻塞界面；来源保留、已有输出拒绝覆盖。如果完整文件已在取消请求前写出，界面提示完成或保留结果。成功后可打开目录或明确加入模型库，完成本身不替换当前模型。默认保存到个人数据目录 `converted-models/`。入库时记录元数据，选用结果会应用任务、类别、输入尺寸与默认归一化，手工标签仍优先；C1 自动选择灰度，C3 仍需按训练预处理选择颜色模式。操作见 [使用指南](https://github.com/misaka-ning/vision-studio/blob/v2.1.0/docs/使用指南.md#转换模型)。

转换使用现有 PyTorch 2.9.1 与新增 ONNX 1.17.0／protobuf 6.33.0，不需要 ONNX Script、ONNX Slim 或独立 ONNX Runtime 导出依赖，不改变工作台设备。为旧版 OpenCV 的部分静态形状及广播限制进行等价规约，保持标准 ONNX；保存前执行图检查及转换环境 Python OpenCV CPU 输出比较，系统 C++ OpenCV、实际图片与 GPU 后端仍需分别验证。裸权重／未知自定义类需要架构定义；本版不提供 ONNX → PT 图转换或原始可训练检查点还原，不承诺未知动态控制流或训练功能完整保留。转换后的模型仍需匹配训练预处理，灰度和左右目在工作台选择。
