# Vision Studio 2.3.0

本版把数据集评估直接接入检测工作台，形成「选模型 → 导入带标注数据集 → 评估目标类 → 分析阈值与错例 → 采用检测配置」的流程。继续使用 C++17／Qt 6.8.3、Fluent 深色界面、全局模型与既有 CPU／NVIDIA GPU 推理后端。

## 同一工作台，两种工作方式

- 新增「YOLO 数据集」输入，读取标准 YAML、images／labels、图片目录／名单／路径列表，默认 Val，可切换 Test／Train。数据集图片进入原输入队列，沿用全部、从当前向后、只检测当前三种范围。
- 「检测预览」叠加 GT 与预测；未推理的标注只是预览，不记作 FN。「评估调优」后台推理与计算指标，不新增独立模型选择或训练流程。
- 预检查显示有效、有框、空标签、缺标签与审核排除数量。空标签可作负样本；缺标签阻止评估。单类足球审核数据可选 metadata，普通 YOLO 数据集无需准备。

## 目标类指标、阈值与错例

原始模型类别映射到一个数据集类别，分别按真实类别范围校验，原始 ID 不重编号。例如 COCO `32: sports ball → 0: football` 只定义评估关系，不使模型变成足球专用。

首版 mAP50／mAP50–95 表示所选目标类别的 AP，不能当作多类总体 mAP。AP 使用低置信度候选；当前阈值下的 Precision／Recall／F1、TP／FP／FN 和无目标图片误报率使用统一最高 IoU 一对一匹配。无目标误报率以确认没有该目标 GT 的图片为分母，未定义值显示 N/A。

评估固定以置信度 0.001 采集候选，每图最多 300 个 NMS 后目标候选、30000 个 NMS 前候选，保留工作台输入尺寸、颜色、预处理、NMS 和设备。默认扫描 0.05～0.95、步长 0.01 的 91 个阈值，可调整范围；曲线、明细、指标与误检／漏检／无目标误报图片联动，复用同一次推理。

完整完成且超过一张图片的集合才显示主 AP；单图、子集、中断任务明确标记范围，描述性 AP 单独保存。仅完整 Val 集提供 F1 最大、最低 Precision 或最高误报率约束下的工作点推荐；条件不满足时明确说明。Test 与 Train 扫描只作描述，不能替代独立验证。

## 从评估回到实际检测

查看曲线和推荐不会自动改参数。点击「采用检测配置」后，才核对模型内容并应用报告中的输入尺寸、颜色、预处理、NMS、设备、原始目标 ID 与所选置信度；随后可在同一工作台运行图片、文件夹、视频或摄像头。

每次评估独立保存配置、输入哈希、标注和低分预测快照、逐图结果、阈值表、错例 CSV、Markdown 及深色 PNG／SVG 曲线。运行记录双击重开，模型库关联最近报告与已采用阈值。导出原始报告附带当前分析选择，历史成绩保持原样。

任务固定范围和顺序，停止不再调度后续图片；已完成前缀在后台保存为中断报告，界面不等待磁盘或报表导出。原始文件或缓存变化会阻止新报告作为有效成绩发布。历史统计可继续查看；原图移动或内容改变时，拒绝将旧预测叠加到新图上。

首版使用完整图像坐标，支持原有彩色／灰度 C1／C3；不提供分类评估、多类总体 mAP、左右目／ROI 裁剪评估、NMS 扫描、模型训练与视频／摄像头在线 mAP。普通检测、录制、转换和结构显示继续保留。

开发测试、手算指标对照、真实模型、最终 DEB、隔离安装、CPU／CUDA、报告导出与完整对应源码的执行结果，见[同版证据](https://github.com/misaka-ning/vision-studio/tree/v2.3.0/docs/releases/evidence/2.3.0/)。仅以实际保存的报告和原始日志认定通过，未执行项目不计入验收；发布前完成本版最终文件的适用核验。Windows 2.3.0 与物理摄像头不作为已实测项目。

正式标签为 `v2.3.0`，Debian 版本为 `2.3.0-1`，默认安装到 `/opt/VisionStudio`。Linux Release 保持三个手动附件：

- `vision-studio_2.3.0-1_amd64.deb`
- `vision-studio-2.3.0-complete-source.tar.xz`
- `SHA256SUMS`

```bash
sha256sum -c SHA256SUMS
sudo apt install ./vision-studio_2.3.0-1_amd64.deb
```

升级前结束检测、评估、录制和转换并退出旧程序。设置、模型、运行记录、导出、录像、评估报告与 GPU 环境保留；新评估位于个人数据目录的 `evaluations/`，不写入安装目录或原数据集。
