# Vision Studio 2.3.1

本版修复 2.3.0 的数据集导入入口只能选择 YAML、无法直接选择文件夹的问题。继续使用 C++17／Qt 6.8.3、Fluent 深色界面和现有 CPU／NVIDIA GPU 后端，评估指标与推理逻辑沿用 2.3.0。

## 直接选择数据集文件夹

- 点击「YOLO 数据集」默认选择数据集根文件夹；同排箭头保留「选择 YAML 配置文件…」入口。
- 只检查根目录，优先采用唯一的 `data.yaml`、`data.yml`、`dataset.yaml` 或 `dataset.yml`，大小写不敏感。没有约定名称时，可采用根目录唯一的 YAML。
- 多个约定配置，或无约定名称且存在多个 YAML 时，明确提示选择配置文件；不扫描子目录、不猜测训练配置、不自动生成类别或改写 YAML。
- 导入仍是只读预检查与 GT 预览，不自动开始整集推理。图片、标注和用户配置保持原样。

## 错误后可以继续重试

首次导入失败后保留待导入位置、集合与可选 metadata，并显示行内错误。可以切换 Train／Val／Test，再点击「重新检查」；数据集未提供 Val 时不会擅自切换到 Train。若已有有效数据集，新的导入失败会恢复原数据集、队列和结果。

YAML 的 `path` 相对配置文件所在目录解析，集合路径相对 `path`。通过文件夹入口导入时，失效的绝对根目录可按所选目录只读迁移：仅映射旧根目录之内且原位置已不存在的集合／名单路径，严格检查成功后显示迁移提示；直接选择 YAML 仍严格使用原配置路径。原配置和数据保持原样，其他路径错误需核对配置。只有 images／labels 而没有标准配置时，应用不会猜测类别或集合。已有评估、三种检测范围、阈值分析、结果回看与配置采用继续保留。

## 验证与文件

本版适用测试与最终包验收待实际执行并记录到[同版证据](https://github.com/misaka-ning/vision-studio/tree/v2.3.1/docs/releases/evidence/2.3.1/)，不沿用 2.3.0 的通过数量或报告结论。验收应覆盖文件夹／YAML 两种真实选择入口、配置候选和歧义、首次失败后切换集合重试、已有数据集的失败恢复，以及适用的真实模型、CPU／CUDA、最终 DEB、安装与对应源码检查。Windows 2.3.1 与物理摄像头不作为已测试项目。

正式标签为 `v2.3.1`，Debian 版本为 `2.3.1-1`，默认安装到 `/opt/VisionStudio`。Linux Release 保持三个手动附件：

- `vision-studio_2.3.1-1_amd64.deb`
- `vision-studio-2.3.1-complete-source.tar.xz`
- `SHA256SUMS`

```bash
sha256sum -c SHA256SUMS
sudo apt install ./vision-studio_2.3.1-1_amd64.deb
```

升级前结束检测、评估、录制和转换并退出旧程序。设置、模型、运行记录、导出、录像、评估报告与 GPU 环境保留；程序不向原数据集或安装目录写入评估结果。

本版远端标签、发布状态、三个附件大小与 SHA256 核验成功后，按规范保留本地 2.3.1 与 2.3.0，并逐版检查旧发行／构建副本后清理。历史远端标签、Linux 核心附件与 2.1.0 Windows 补充包保持原样。
