# Vision Studio 2.0.0

2.0 正式版的本轮开发集中改进参数输入、批量停止响应、保存目录入口与模型库排序。Fluent 深色界面、批量检测结果回看、CPU／NVIDIA GPU、ONNX／PT、灰度 C1／C3、左右目、录像、导出与模型三视图保留。

## 本轮四项改进

- **参数防误改**：输入尺寸、置信度和 NMS IoU 禁用鼠标滚轮改值，经过控件滚动页面时不再改变参数；使用数值输入、键盘或步进按钮调整。
- **批量停止响应**：修复图片结果积压、缓存和自动导出阻塞界面导致的停止卡顿。结果按后台保存完成的节奏交付，临时缓存、标注绘制、自动导出和历史写入移至后台；停止不等待保存完成。已交付结果可回看，已接受的写入收尾后恢复下一任务入口。
- **打开保存目录**：自动保存每张图片的选项下方提供「打开保存文件夹」按钮，直接查看实际自动导出目录中的结果。
- **模型排序持久化**：模型库支持拖动排序，退出并重启后恢复顺序；仅重排位置不改变当前全局模型，检测工作台与模型显示保持使用同一选中模型。

ONNX CPU 的当前 OpenCV forward 不能强制中断，但运行和保存均不占用界面线程，停止后不再处理后续图片；CUDA 保留 ONNX Runtime 终止请求，PT 保留子进程取消。关闭窗口也异步等待已接受的写入完成，不在主线程阻塞收尾。停止耗时取决于当前后端、模型和所处阶段，不承诺统一的毫秒数。

## 保留的界面与结果行为

Fluent-Qt v1.9.2 仅作暗色视觉参考，原始 MIT 与固定来源保留，不新增 FluentQt 运行依赖。窗口、卡片、控件、表格与模型三视图保持统一深色对比。

批量完成后可恢复每张已完成图片的检测框、类别、置信度、目标表、指标和导出对象。零目标结果有效，关闭自动导出也可回看；浏览结果不重复推理、追加运行记录或再次自动导出。未处理图片只显示原图，手动导出使用当前选中图片及原始推理配置。临时缓存在新任务、来源／模型／预览模式／设备变化或关闭程序时释放，永久保存仍需导出。这些回看行为已在 Beta.2 提供，属于正式版保留的基线。

模型库的选择全局决定检测和结构显示使用的文件，后台预加载及页面／模式缓存复用保留。普通 PT 的模块包含关系和权重分组不能表达完整 forward，查看完整运算图建议使用导出的 ONNX。

## 兼容范围

目标平台为 Ubuntu 22.04 LTS amd64、C++17／Qt 6.8.3。CPU ONNX 使用 OpenCV DNN，可选 NVIDIA ONNX 使用 ONNX Runtime CUDA；PT 使用本地常驻 PyTorch，兼容现代 Ultralytics 完整检查点、YOLOv5 v7.0 完整检查点及具备必要元数据的标准 TorchScript。

保留灰度 C1／C3、单设备左右水平拼接视频／摄像头的单目处理、检测和单标签分类、录像与原有导出格式。TensorRT、AMD／Intel GPU、分割、姿态和旋转框未提供；ONNX 还应符合固定 1／3 通道 NCHW、单运行时图像输入及原始检测／分类输出约定，详见 [模型说明](https://github.com/misaka-ning/vision-studio/blob/v2.0.0/docs/模型说明.md)。

CPU／Netron 环境随包提供；GPU 初次需在「更多」主动准备，使用官方依赖的完整版本与 SHA256 锁配置独立用户环境，实际 CUDA 自检通过后发布。不更改驱动，不在 APT／DPKG 安装时下载 GPU 依赖。物理摄像头按实际设备另行验证。

## 文件、安装与升级

应用版本与发行目录为 `2.0.0`，标签为 `v2.0.0`，Debian Control Version 为 `2.0.0-1`。正式 Release 使用 `prerelease=false` 并更新 Latest。三个手动附件为：

- `vision-studio_2.0.0-1_amd64.deb`
- `vision-studio-2.0.0-complete-source.tar.xz`
- `SHA256SUMS`

```bash
sha256sum -c SHA256SUMS
sudo apt install ./vision-studio_2.0.0-1_amd64.deb
vision-studio
```

默认安装到 `/opt/VisionStudio`。正式包版本高于 Beta.2 的 `2.0.0~beta.2-1`，可直接升级。先停止检测与录像、导出需要保存的结果、退出旧程序，再安装并启动新版；个人设置、模型、运行记录、导出、录像和已有 GPU 环境保留。临时回看缓存不会跨重启保存。

应用代码采用 AGPL-3.0-only；第三方组件保留原始许可。完整源码包重新生成本版应用归档和清单，保留同一套 15 份原始上游源码及通知；GitHub 自动提供的源码 ZIP／tar.gz 不能替代完整对应源码包。QA 随仓库提交，不作为额外 Release 附件。

标签、发布状态与三个资产的大小／SHA256 全部核验后，本地保留 2.0.0 与 1.6.0 的发行和独立构建副本；旧 Beta 副本逐版精确核验后清理。工作树、用户数据、共享 SDK／runtime 保留，已公开标签、资产和原始归档不可覆盖。
