# 开发指南

本页面向从 Git 源码运行和修改 Vision Studio 的开发者，承接首页的构建、测试和环境配置说明。普通安装请从[首页下载入口](../README.md#下载与快速开始)开始；重建已发布 DEB 及其第三方组件请阅读[对应源码与重建](release/对应源码与重建.md)，开发环境不能直接替代发行运行环境。

## Linux 开发构建

### 环境要求

- CMake ≥ 3.21、Ninja、支持 C++17 的编译器和 Git。
- Qt 6.8.3 SDK：Core、Gui、Widgets、Svg、Network、WebChannel、WebEngineWidgets；测试还需要 Test。WebEngine 需配套 Quick／Qml／Positioning 模块及运行资源。
- OpenCV ≥ 4.5，包含 Core、Imgproc、Imgcodecs、Videoio、DNN。Linux 发行基线使用 Ubuntu 22.04 与 OpenCV 4.5.4。
- Python 3.10 或 3.11，包含 venv；PT、Netron、模型转换及评估需准备 Python 环境。

以下按 Qt SDK 位于 `$HOME/Qt/6.8.3/gcc_64`、系统 Python 位于 `/usr/bin/python3.10` 编写；按本机实际位置调整。初次准备依赖需要网络。

```bash
git clone https://github.com/misaka-ning/vision-studio.git
cd vision-studio
VISION_STUDIO_BASE_PYTHON=/usr/bin/python3.10 ./scripts/setup_pt.sh

cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH="$HOME/Qt/6.8.3/gcc_64" \
  -DBUILD_TESTING=ON \
  -DVISION_STUDIO_TEST_PYTHON="$PWD/runtime/bin/python"
cmake --build build --parallel 4
./build/bin/vision-studio
```

`setup_pt.sh` 在源码目录的 `runtime/` 建立开发环境，使用 `requirements-pt.txt` 与 `requirements-pt.lock.txt`。也可使用 `VISION_STUDIO_PYTHON="$PWD/runtime/bin/python" QT_PREFIX="$HOME/Qt/6.8.3/gcc_64" ./scripts/build.sh` 完成配置、构建和完整 CTest；此脚本包含测试步骤，不只是编译。运行普通应用不会自动载入示例，可自行导入仓库示例或自己的可信模型与输入。

### 测试与 Smoke

准备好对应依赖后执行完整测试：

```bash
VISION_STUDIO_PYTHON="$PWD/runtime/bin/python" \
  ctest --test-dir build --output-on-failure
```

`VISION_STUDIO_TEST_PYTHON` 是 CMake 的测试解释器缓存路径；切换环境后应重新配置。缺少解释器或依赖的评估测试会失败，不能把未执行的后端或被跳过的测试当作通过。真实 CUDA、PT、转换等检查还需要相应模型、运行环境和硬件，具体要求见[打包验收](../packaging/README.md#验证与发布)。

现有 CLI Smoke 可用于真实示例检查，输出写入指定目录：

```bash
./build/bin/vision-studio --smoke ./output/smoke/onnx
./build/bin/vision-studio --smoke-pt ./output/smoke/pt
./build/bin/vision-studio --smoke-model ./output/smoke/model
```

这些命令会实际运行应用及相关后端，模型显示还涉及 WebEngine；需要相应运行环境与图形／测试显示环境。Smoke 是开发验证入口，不替代最终安装包验收。本页整理命令，不据此声明本次文档修改重新执行了构建或模型回归。

### NVIDIA GPU 开发环境

ONNX CPU 使用 C++ OpenCV DNN，ONNX CUDA 使用 C++ ONNX Runtime，PT／TorchScript 使用常驻 Python／PyTorch；具体设备与回退以运行结果为准。GPU 与 CPU／Netron 环境分开，首次准备可通过「更多」完成，或执行：

```bash
./scripts/setup_gpu.sh
/usr/bin/python3.10 scripts/gpu_probe.py
```

脚本默认使用系统 Python 3.10，不跟随 PATH 中的 Conda；可用 `--base-python /绝对路径/python3.11` 和 `--runtime-dir /用户专用目录/gpu-runtime` 指定环境，并通过 `VISION_STUDIO_GPU_RUNTIME_DIR` 在应用中选择同一目录。GPU 依赖采用独立的 `requirements-gpu.txt`／`requirements-gpu.lock.txt` 和官方 wheel SHA256 锁，不安装或修改显卡驱动。

当前锁定 PyTorch `2.9.1+cu128`、Torchvision `0.24.1+cu128`、CUDA 12.8、cuDNN 9.10.2、ONNX Runtime 1.23.2；推荐 Linux NVIDIA 驱动 ≥ 570.26，不要求全局 CUDA Toolkit。下载体积、空间需求与设备边界见[模型说明](模型说明.md#v16-计算设备与-gpu-模型)和[使用指南](使用指南.md#cpu-与-nvidia-gpu)。TensorRT、AMD 与 Intel GPU 尚未提供。

## Windows 开发构建

使用 Qt 6.8.3 MSVC 2022 64 位 SDK、MSVC x64、Ninja 和兼容的 OpenCV Windows 动态库。已发布 Windows 2.9.1 的基线为 OpenCV 4.12.0，实际测试系统与限制见[Windows 证据](releases/evidence/2.9.1/windows/README.md)；这不表示主线 2.10.1 已完成 Windows 验收。

Qt 需安装 WebEngine、WebChannel、Svg 及配套模块。在 Visual Studio x64 开发者终端中执行，按实际 SDK 位置调整路径：

```powershell
cmake -S . -B build-windows -G Ninja -DCMAKE_BUILD_TYPE=Release `
  -DBUILD_TESTING=ON -DCMAKE_PREFIX_PATH=D:/Qt/6.8.3/msvc2022_64 `
  -DOpenCV_DIR=D:/Opencv-C++/opencv/build/x64/vc16/lib
cmake --build build-windows --target vision-studio --parallel 4
D:/Qt/6.8.3/msvc2022_64/bin/windeployqt.exe --release build-windows/bin/vision-studio.exe
# 将对应 OpenCV 的 opencv_world DLL 和 videoio_ffmpeg DLL 复制到 build-windows/bin
./build-windows/bin/vision-studio.exe --device cpu
```

开发构建仍需准备资源及兼容 Python 环境；可用 `VISION_STUDIO_PYTHON` 指向所选解释器。正式可分发环境、Windows CUDA 锁、CPU 运行 ZIP、Inno Setup 双安装包及 Windows FFmpeg 对应源码以[Windows 打包说明](../packaging/windows/README.md)为准，不直接把开发目录当作安装器。

## 运行环境与源码位置

| 配置 | 用途 |
| --- | --- |
| `VISION_STUDIO_BASE_PYTHON` | `setup_pt.sh` 创建开发 runtime 的 Python 3.10／3.11 解释器 |
| `VISION_STUDIO_PYTHON` | 应用使用的兼容 Python 解释器绝对路径 |
| `VISION_STUDIO_TEST_PYTHON` | CMake 中评估 Python 测试的 FILEPATH 缓存变量 |
| `VISION_STUDIO_DATA_DIR` | 独立的个人数据目录；测试时避免写入日常配置与输出 |
| `VISION_STUDIO_GPU_RUNTIME_DIR` | 独立 GPU 环境目录 |
| `VISION_RESOURCE_FALLBACK` | CMake 资源回退根，默认源码根目录；生产打包使用匹配安装路径 |

正式 DEB 的无 GUI OpenCV runtime 使用[发行依赖锁](release/requirements-release.lock.txt)，不能用开发锁替代。CPU／Netron 环境与 GPU 环境的版本、通知和对应源码须分别保留；完整交付步骤见[对应源码与重建](release/对应源码与重建.md)。

代码职责与目录说明集中在[应用架构](architecture/应用架构.md)，包括 `vision-ui → vision-app → vision-core`、领域状态、结果交付和异步关闭；不在本页重复维护模块清单。
