# YOLO 模型 YAML 展示调研

状态：可行性与接入设计，尚未实现。本文不属于 2.6.0 已交付功能。

## 适合增加的展示方式

在现有「结构图／模块目录／参数」旁新增「YOLO YAML」只读视图，沿用模型库中的全局选择、后台预加载和文件身份缓存。进入页面或切换展示模式不重复解析模型，不改变推理、模型转换或用户文件。

官方的 `# [from, repeats, module, args]` 表达每层的来源、重复次数、模块名与构造参数；`backbone` 和 `head` 定义网络连接。`from` 可以是相对索引或多个来源，`repeats` 还会受深度缩放影响，不能直接解释成实际执行层数。不同模块的 `args` 含义不同。现代配置可能使用 `scales`，旧配置可能使用 `depth_multiple`、`width_multiple`；YOLOv5 的 anchors 不能套用于所有 YOLO。

参考：[Ultralytics 官方配置指南](https://docs.ultralytics.com/guides/model-yaml-config/)、[当前解析实现](https://github.com/ultralytics/ultralytics/blob/main/ultralytics/nn/tasks.py)、[YOLOv5 v7.0 解析实现](https://github.com/ultralytics/yolov5/blob/v7.0/models/yolo.py)。

## 实际文件中的可获得信息

对项目公开示例文件的静态检查表明，`yolov8n.pt` 和 `yolov5n.pt` 的检查点保留了架构字典，可以整理成这种 YAML。它们没有附带原始 `.yaml` 文件内容，所以原始注释、排版和训练时配置路径不能完整还原。应显示「从模型元数据生成的等价架构配置」，不能标成「原始训练 YAML」。

已检查的两个 YOLOv5 ONNX 没有架构元数据；已检查的 TorchScript 只有任务、类别、输入形状等配置，不能据此恢复 YOLO 的 `backbone/head`。这只是已检查文件的结论，不能推断所有同格式文件均如此。缺少结构字典时显示「此模型未包含可恢复的 YOLO 架构配置」，保留现有结构图；不能根据文件名猜测网络。

## 与现有代码的连接点

- `src/ui/modelviewer.cpp` 已通过 Netron 浏览器端解析模型并提取结构，优先从该已解析对象取出受限的架构字典，扩展现有结果，不额外加载权重。
- 使用独立 schema、大小／层数／递归深度限制和允许类型校验；只接受字符串、有限数字、布尔值、空值、列表和白名单字段字典。未知对象、异常引用或不完整层定义明确失败。避免为了查看结构执行 `torch.load` 或 Python pickle 反序列化。
- 按 `nc`、缩放参数、anchors（存在时）、`backbone`、`head` 输出稳定的 YAML；每节加入四字段说明。按实际模型内容显示，不自动套用同名官方模板。动态实际层与蓝图缩放含义在小字提示中说明。
- 原结构缓存增加 YAML 文本与来源状态。模型切换、同路径文件变化和快速异步切换使用现有 generation 检查，拒绝旧回调。
- Qt 只读等宽编辑控件配合语法高亮：深灰背景、浅色正文、青蓝键名和模块名、可读的灰色注释。支持搜索、复制和另存 YAML；不在首版提供编辑后构建模型。

## 实现与验收边界

首版可以覆盖已含架构字典的现代 Ultralytics PT 和旧 YOLOv5 PT，无新增运行依赖；先对当前 Netron 解码对象的字段实际取值做原型验证。若当前解析器不暴露该字典，应增加受限静态读取，而非改为执行模型。另行导入用户提供的原始 YAML 可作为后续功能，必须与生成配置区分来源。

验收应使用真实示例验证字段、层顺序、多来源索引、重复与缩放参数；覆盖不支持的 ONNX／TorchScript、无 YAML 的 PT、畸形或超限数据、快速切换、后台缓存复用与深色可读性。验证展示过程中没有触发推理、权重执行或修改源模型。完成上述实现和验收后再将其列入相应版本更新日志。
