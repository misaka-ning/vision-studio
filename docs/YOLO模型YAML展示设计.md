# YOLO 模型 YAML 展示设计

状态：已接入 2.7.0 工程，完整验收与发布结果待验证。本文保留前期静态调研结论并说明实际实现，不将设计说明当作已通过测试的证明。使用操作见 [使用指南](使用指南.md#全局模型与结构显示)，最终结果见 [2.7.0 证据](releases/evidence/2.7.0/README.md)。

## 四种视图与来源

「模型显示」在结构图、层级树和参数表之后提供「YOLO YAML」。四种模式共用模型库的全局选择、Netron 后台解析、文件身份和 generation 检查；切换页面或模式复用缓存，不执行一次模型推理生成蓝图，也不改变当前检测或评估配置。

读取路径为 `modelviewer.cpp` 中已解析 Netron 对象 → `modelyaml.cpp` 的受限架构字典提取 → C++ 字段校验和 YAML 生成 → Qt 只读视图。不另起 Python 权重反序列化，不执行 `torch.load`、`eval`、模型类或 forward，也不扫描权重张量值。文件保存的架构来源名仅作信息，不据此读取外部 YAML。

## 架构语义

`backbone` 和 `head` 按 `[from, repeats, module, args]` 保存网络蓝图；`from` 可以为相对索引或多个来源，`repeats` 会受深度缩放影响，模块参数和通道也可能受宽度缩放影响。现代配置可能使用 `scales`，旧配置可能使用 `depth_multiple`／`width_multiple`；YOLOv5 anchors 不适用于所有 YOLO。

输出明确标注「从模型保存的架构字典生成等价配置；不是原始 YAML」。原始注释、排版、训练代码与配置路径不可恢复，蓝图不能等同实际算子列表或张量 shape，也不承诺导出后可直接复现任意训练工程。

参考：[Ultralytics 配置指南](https://docs.ultralytics.com/guides/model-yaml-config/)、[YOLOv5 v7.0 解析实现](https://github.com/ultralytics/yolov5/blob/v7.0/models/yolo.py)。实际字段以模型自身保存的值为准。

## 前期静态调研的范围

前期对随附 `yolov8n.pt` 和 `yolov5n.pt` 的静态检查发现架构字典，未发现可完整恢复的原始 YAML 文本；已检查的两个 YOLOv5 ONNX 没有该字典，已检查 TorchScript 只有任务、类别和输入等信息。这些结论只适用于检查过的文件，不代表所有同扩展名文件。

生产实现逐文件判断：缺少字典、裸权重、无法恢复配置的运算图或不支持结构时显示具体原因，保留其他已有视图。不能根据文件名猜测网络、套用官方模板、把部分层或任意字典标成完整训练 YAML。

## 校验与显示边界

提取只接受受限原始容器、字符串、有限数字、布尔值和空值；拒绝循环引用及未知对象。C++ 再检查允许字段、`nc`、缩放、anchors、来源索引和四字段层定义；元信息及生成文本限制为 256 KiB，最多 2000 层、20000 个值、深度 12。异常或超限时给出说明，不输出看似完整的截断配置。

生成文本为只读等宽深色编辑器，语法高亮区分键名、模块和注释。支持搜索、回车定位下一处、复制和另存 YAML／YML；模型切换后清理旧内容，拒绝旧异步回调，加载成功后进入视图无需重解析。

另存只允许新的文件名；同目录暂存后提交新文件，拒绝源模型、已有文件、符号链接和并发同名目标。源模型与已有文件内容保持，失败显示错误；不提供编辑、训练或重新构建网络的操作。实现使用 C++17／Qt 6.8 与现有 Netron，不新增运行依赖。

## 本版验收要求

必须使用实际现代 Ultralytics PT、旧 YOLOv5 PT、ONNX 和 TorchScript，检查架构字段、层顺序、多个来源、重复与缩放，以及缺失元信息提示。还需覆盖裸权重、畸形与超限、源文件变化、快速切换、缓存复用、深色可读性、搜索／复制／导出及已有文件保护。展示检查不得通过模型推理或执行 pickle 获得结构；原始模型和外部资料应保持不变。结果和限制保存到同版证据，未执行不记通过。
