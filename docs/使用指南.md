# Vision Studio 使用指南

## 全局模型与结构显示

在「模型库」点击模型即可全局选用；「检测工作台」与「模型显示」始终使用这个模型。「前往检测工作台」和「查看模型结构」只切换页面。导入模型和运行示例也会同步更新全局模型。

选择模型后，应用在后台异步解析并排列结构，完成后保留本次运行的图形缓存。进入或离开「模型显示」不会重复加载，原来的缩放、平移和节点详情也会保留。切换模型会加载新结构；格式不受支持或文件损坏时显示文字说明，可以点击「重试加载」。

在模型显示页切换「结构图」「层级树」「参数表」检查同一个模型。三种模式复用一次解析缓存，切换无需重新加载模型；使用搜索定位内容，再查看对应详情。结构图用于查看节点与连接，层级树用于浏览可解析的模块或权重分组，参数表用于集中核对参数与张量信息。图中嵌套对象和详情也使用深色背景与可读文字。

结构图使用 Netron 内置查找。层级树的搜索匹配名称、类型和路径，保留匹配项的祖先，便于沿层级定位；参数表可按路径、dtype、shape、元素数或备注查找。点击条目查看文件中可靠保存的元信息。表可包含权重、常量和缓冲，不代表可训练参数总量，也不统计运行激活。大型模型超出显示限额时会提示截断。选择新模型后旧搜索与详情会清除，当前模式保持不变。

结构由随包的 Netron 9.3.1 在本机显示。ONNX 展示文件内的运算图；普通 `.pt` 的包含关系、权重分组和静态信息不代表完整 forward，应用不会补造运算连接，也不会为查看结构执行 `torch.load`。所有非 ONNX 文件都会显示一行提示：

想看完整结构，建使用导出的 ONNX。

## 完成第一次推理

1. 启动 Vision Studio，在「更多」中点击「运行示例」。等待模型加载，工作台会显示示例图片、检测框和目标列表。
2. 导入自己的 `.onnx` 或 `.pt` 模型。ONNX 检测模型选择 YOLOv5 或 YOLOv8 / YOLO11，分类模型选择图像分类。现代 Ultralytics `.pt` 使用模型自带的任务与类别信息。
3. ONNX 自定义检测模型需导入标签文件。标签按类别 ID 顺序排列，每行一个类别，例如 `person`、`bicycle`、`car`，数量必须与输出类别数一致；默认检测标签为 COCO 80 类。`.pt` 自动读取类别名称，也可导入数量匹配的标签来覆盖名称。
4. 选择图片、图片文件夹、视频文件或摄像头。图片可加入队列后批量运行。
5. 选择与模型训练一致的彩色或灰度输入，调整输入尺寸、置信度和 NMS 阈值，点击「开始检测」。
6. 查看结果，在「更多」中点击「导出结果」。图片批量任务需要逐张保存时，可启用自动导出。

## 计算设备与 GPU 准备

在工作台选择「自动 · 优先 NVIDIA GPU」「CPU」或「NVIDIA GPU」，多卡电脑可选择 GPU 编号。自动模式优先使用已准备的 GPU，无法使用时说明原因并使用 CPU；显式 GPU 模式失败时给出错误，避免把 CPU 结果当作 GPU 结果。运行期间锁定设备选项，切换设备后需重新载入模型。状态和导出的设备字段记录实际执行设备。

首次使用 NVIDIA GPU，进入「更多」点击「检查 GPU 环境」。检测到显卡不代表推理依赖已准备；点击「准备 GPU 支持」从官方源下载约 4–5 GB，建议预留至少 20 GB 空间。进度条和日志显示准备阶段，可以点击「取消准备」。下载、校验或实际 CUDA 自检失败时报告原因，并保留原来的 CPU／已就绪 GPU 环境。

GPU 依赖安装至个人数据目录的 `gpu-runtime/`，与 `/opt/VisionStudio/runtime` 中的 CPU／Netron 环境独立。不修改显卡驱动，也不需要全局 CUDA Toolkit。正式 DEB 声明系统 Python 3.10 venv 依赖，APT 安装时不会自动下载 GPU wheel；GPU 初次配置完成后可离线推理。推荐 Linux NVIDIA 驱动 ≥ 570.26；显存不足、算子不支持或 GPU 不可用时可改选 CPU。TensorRT、AMD、Intel GPU 尚未支持。

命令行配置与只读检查：

```bash
/opt/VisionStudio/scripts/setup_gpu.sh
/usr/bin/python3.10 /opt/VisionStudio/scripts/gpu_probe.py
```

源码目录使用 `./scripts/setup_gpu.sh` 和 `/usr/bin/python3.10 scripts/gpu_probe.py`。默认明确使用系统 Python 3.10，避免 PATH 中不兼容的 Conda 解释器。可指定 `--runtime-dir /用户专用目录/gpu-runtime`，并在启动应用前设置 `VISION_STUDIO_GPU_RUNTIME_DIR` 为同一绝对路径；未知内容或符号链接目录会拒绝安装。

CPU ONNX 使用 C++ OpenCV DNN；GPU ONNX 使用 C++ ONNX Runtime 1.23.2 CUDA。PT 三类受支持的模型均通过本地 PyTorch 执行，GPU 环境为 `2.9.1+cu128`。颜色、灰度 C1／C3、左右目及后处理设置在不同设备上保持一致。Netron 可视化继续使用 CPU 环境，与计算设备选择无关。

## 选择模型参数

ONNX 在 C++ OpenCV（CPU）或 ONNX Runtime（GPU）中执行；`.pt` 由本机独立 PyTorch runtime 执行，界面仍为 C++ / Qt。工作台会显示所用后端。

**输入尺寸**是模型接收的正方形图像宽高。例如模型导出为 640 × 640，则填写 640。动态尺寸模型也需确认模型允许选择的尺寸。固定尺寸模型填错可能导致推理失败。

**置信度阈值**过滤低分目标。调低可显示更多候选目标，也可能增加误检。**NMS 阈值**控制同类别检测框的重叠抑制；数值越低，重叠框越容易被合并。不同类别的框会保留。

**RGB 通道、缩放系数和均值**需与模型训练及导出时的预处理一致。常见 YOLO 模型使用 RGB、系数 `1 / 255`、均值 0。分类模型可能采用其他均值或缩放方式，应以模型说明为准。当前界面支持统一缩放系数及各通道均值，暂未提供各通道标准差设置。

上述手工预处理适用于 ONNX。现代 YOLO `.pt` 使用 Ultralytics 的原生图像预处理与 NMS；保留默认 RGB、`1 / 255` 和零均值配置。应用会拒绝不受支持的 `.pt` 手工预处理，避免参数被静默忽略。

## 使用灰度 ONNX 模型

在工作台选择「灰度」输入模式。应用从 ONNX 的 NCHW 图像输入解析通道数：`[1,1,H,W]` 接收单通道灰度，`[1,3,H,W]` 接收三份相同的灰度值。彩色输入按亮度权重转换为 8 位灰度，随后执行缩放、补边和模型所需的归一化。

灰度模式只使用一个均值（原 R 均值）；缩放计算为 `(灰度值 - 均值) × 缩放系数`。三通道灰度统一使用该均值，G / B 均值配置不参与，RGB / BGR 切换不会改变灰度值。检测仍保持比例并用 114 补边，分类仍缩放到正方形。

模型输入通道数自动解析，不需要把图片手工改成灰度文件。灰度推理后的画布和 PNG 标注底图显示实际灰度，仍保持所选画面的尺寸。切回 RGB / BGR 后恢复原色，旧检测框、目标列表和指标会清除，需重新运行后再导出。

默认仍为彩色，旧版保存的设置继续使用彩色。单通道模型若选择彩色会提示改用灰度。当前 ONNX 仅支持固定的 1 或 3 通道；动态通道、4 通道、多个运行时图像输入和非四维 NCHW 输入需重新导出为兼容模型。动态宽高的算子兼容性仍由 OpenCV 决定。

选择灰度不会把彩色训练的模型自动变成灰度模型；应使用训练时相同的颜色转换和归一化。

## 使用单设备左右拼接摄像头或视频

选择对应摄像头编号或打开视频，在画面选择中使用「完整画面」「左目」或「右目」。这适用于一个设备输出左右水平拼接画面的情况。应用保留摄像头默认分辨率，实际裁切尺寸由采集到的源帧决定。

| 画面选择 | 推理图像 |
| --- | --- |
| 完整画面 | 原始整帧 |
| 左目 | 从最左列开始取 `floor(原始宽度 / 2)` 列 |
| 右目 | 从上述分界列开始取剩余列，奇数宽度时比左目多一列 |

例如 1280 × 480 的拼接帧，左目与右目各为 640 × 480；宽度 129 的帧分别得到宽度 64 和 65。裁切在模型预处理之前完成，之后按彩色 / 灰度和输入尺寸设置执行推理。

工作台预览、检测框坐标和 PNG 标注都以所选画面为准。右目的 `x=0` 是右目画面的左边界。JSON 保存画面选择与原始帧尺寸，便于追溯来源。视频或摄像头结束后的自动导出仍使用最后一帧。图片队列保持完整图像，即使上次摄像头选择了左目或右目，也不会裁切图片。

ONNX 检测图像会保持比例缩放并补边；ONNX 分类图像会直接缩放至正方形。分类输出若为 logits，应用进行 softmax 后显示概率；若已是归一化概率，则保留原值。分类显示概率最高的 5 个类别（类别少于 5 个时全部显示），置信度与 NMS 阈值用于检测任务。Ultralytics `.pt` 与兼容的 TorchScript 分类均采用 Ultralytics 标准分类图像变换，以 PIL RGB 图像输入 `classify_transforms`；模型需与该预处理匹配。

## 使用 .pt 检查点

选择自己训练或可信来源的现代 Ultralytics YOLOv8 / YOLO11 `.pt`，直接导入并运行。完整检查点提供模型架构和类别信息；只有 `state_dict` 的权重字典需要额外架构，不能直接作为完整模型使用。

标准 YOLOv5 完整检查点由随附的 `vendor/yolov5` v7.0 兼容框架加载，`models/yolov5n.pt` 为真实示例。训练时新增的自定义模块仍需要原项目代码。TorchScript `.pt` 需提供任务、类别名称元数据，并具有标准原始检测输出或单标签分类输出。

现代 Ultralytics、兼容 YOLOv5 与标准 TorchScript 的 1 / 3 通道模型可选择灰度输入。通道数从实际模型输入层读取；TorchScript 无法可靠识别输入层时，应在导出归档内的 `config.txt` JSON 对象中加入 `"input_channels": 1` 或 `"input_channels": 3`。声明与模型输入层冲突会报错。彩色模式要求 3 通道。

`.pt` 灰度检测先按亮度转换，单通道模型接收一个通道，三通道模型接收三份灰度；随后 letterbox、除以 255 并使用模型后处理。`.pt` 检测的输入尺寸须为 32 的倍数，否则载入时会提示调整尺寸。灰度分类使用 Ultralytics 分类图像变换，明确设定所有通道 `mean=0`、`std=1`，再按模型通道数输入。手工 ONNX 均值和缩放不用于 `.pt`；保留缩放 `1 / 255`、零均值，灰度不受 RGB / BGR 切换影响。

`.pt` 第一次加载需要启动 Python 并载入 PyTorch。后续图片与视频帧复用同一后台模型。正式 DEB 和本机主文件夹中的安装已包含独立 CPU `runtime`。早期 `scripts/package.sh` 生成的便携目录不携带此环境，需要准备 Python 3.10 或 3.11，在该目录先运行 `./scripts/setup_pt.sh` 下载并安装锁定版本的依赖。准备完成后推理可离线执行。使用其他解释器时，在启动前将 `VISION_STUDIO_PYTHON` 设置为其绝对路径，并确认其中安装了相应版本的依赖锁。

PyTorch 检查点载入可能通过 pickle 执行 Python 代码，应使用自己训练或来源可信的文件。

## 查看图像和结果

中央画布展示所选画面和预测，彩色 / 灰度显示与输入模式一致。适应视图让整张图像可见；缩放和拖动画布便于检查细节。显示检测框、显示标签可独立切换。右侧目标表记录类别、置信度与位置。

| 画布操作 | 作用 |
| --- | --- |
| 滚轮 | 以鼠标位置为中心缩放 |
| 鼠标拖动 | 平移图像 |
| 双击，或按 `F` / `0` | 适应视图 |
| 按 `1` | 原始尺寸 |
| 按 `+` / `-` | 放大 / 缩小 |
| 方向键 | 平移图像 |
| 点击检测框 | 定位到对应预测 |
| 按 `Esc` | 取消画布选择 |

键盘操作需要画布获得焦点，可先点击图像。

「推理耗时」只衡量模型 forward；总耗时还包含图像预处理和结果解码。视频与摄像头以逐帧方式处理，实际速度取决于所选 CPU／GPU、输入尺寸与模型规模。UI 更新和导出也会增加运行开销。

推理期间可以点击「停止运行」。ONNX CPU 在当前 OpenCV forward 完成后停止；ONNX CUDA 向 ONNX Runtime 发出终止请求，取消完成后可重新运行；`.pt` 会终止后台推理进程，随后可以重新运行并加载模型。程序退出会等待工作线程清理。

## 录制与查看标注视频

1. 在工作台选择视频或摄像头，设置完整 / 左目 / 右目及彩色 / 灰度，点击「开始检测」。图片队列不提供录制。
2. 推理期间点击「开始录制」，按钮变为「结束录制」。录制保存所选画面的实际颜色模式，并叠加检测框、标签和置信度。
3. 点击「结束录制」完成当前录像，推理可以继续。等待「正在保存…」结束后，在「录制视频」页查看文件。源视频结束、停止推理或退出时会收尾当前录像。
4. 在列表选择录像，点击「播放录像」或「暂停播放」检查结果；可以刷新列表、打开录像文件夹或导出录像。

默认文件位于用户数据目录的 `recordings/`，每次录制产生 MJPEG `.avi` 与同名 `.json`。元数据记录帧数、帧率、时长、内容及编码尺寸、颜色模式、所选眼、源帧尺寸、模型和来源。文件在写入器关闭并校验后才显示为已完成录像。录制只包含已处理的图像帧，不包含音频。

录像覆盖每个实际推理帧，不受工作台预览刷新节流影响。视频文件使用来源帧率；摄像头按实际录制时长确定播放帧率，保留处理到的全部帧。为了兼容 MJPEG，奇数宽高会在右侧或底部复制一行 / 列补为偶数，元数据保留实际内容尺寸，应用播放时裁回内容画面。

## 导出与运行记录

导出结果包含带叠加标注的 PNG、JSON 和 CSV。手动导出入口位于「更多」，原有导出快捷键仍可使用。PNG 使用当前所选图像尺寸与颜色模式绘制完整检测框与标签；分类 PNG 展示概率最高的类别。JSON 记录 `source`、`model`、`task`、`backend`、`requested_device`、`actual_device`、`device_index`、`device_name`、`device_notice`、图像宽高、帧号、推理与总耗时及 `predictions`；`config.color_mode` 和 `config.input_channels` 保存模型输入模式及通道数，`stereo_view` 与 `source_frame_size` 保存画面选择和原始帧尺寸。每个预测包含 `class_id`、`label`、`confidence`、`x`、`y`、`width`、`height`。检测坐标相对所选图像；图片与完整画面对应原图，左右目对应所选眼图。CSV 为每个预测保存一行，适合在表格工具中进一步分析。分类任务的位置字段为 0。

空检测结果也属于有效结果，意味着当前参数下没有目标超过阈值。自动导出会逐张保存图片队列的结果；视频与摄像头在任务结束后保存最后一帧。需要连续标注视频时，可在视频或摄像头推理期间使用「开始录制」，录像在「录制视频」页查看。运行记录提供最近 200 次图片推理或视频任务的摘要，完整图像与预测应通过导出保存。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| ONNX 模型加载失败 | 确认文件存在，核对当前实际后端、输入输出约定及其算子支持。 |
| 检测到显卡但 GPU 不可用 | 到「更多」准备依赖并检查环境；`nvidia-smi` 的 CUDA Version 只是驱动支持上限。 |
| GPU 准备失败／被取消 | 查看日志，保留 CPU 使用；检查网络和剩余空间后重试。未知目录需要换专用目录。 |
| GPU 显存不足 | 选择较小模型、减小输入或改选 CPU；显式 GPU 模式会报告错误。 |
| 提示单通道模型需要灰度 | 选择「灰度」输入模式，并核对训练时的预处理。 |
| 提示 ONNX 通道无法确定或不支持 | 导出固定 1 / 3 通道的四维 NCHW、单运行时图像输入模型；动态宽高和通道数是不同设置。 |
| `.pt` 提示 Python 不存在 | 检查交付目录的 `runtime/bin/python`，或修正 `VISION_STUDIO_PYTHON`。 |
| `.pt` 提示只有 state_dict | 提供包含模型架构的完整 Ultralytics 检查点；仅有权重字典无法确定网络结构。 |
| `.pt` 提示缺少模块或模型类 | 检查 runtime 依赖，并确认检查点来自受支持的现代 Ultralytics YOLO。 |
| 输出维度不匹配 | 核对任务类型；重新导出不带 NMS 的原始检测输出。 |
| 检测框位置不对 | 确认输出是中心点加宽高，坐标以模型输入像素为单位。 |
| 类别名称不对 | 标签文件应与训练类别顺序一致，不能仅按字母排序。 |
| 结果为空 | 检查图像内容、阈值、任务类型和预处理配置。 |
| 分类结果异常 | 检查输入尺寸、RGB / BGR、缩放系数和均值。带各通道标准差的预处理需由模型自身实现。 |
| 摄像头打不开 | 尝试其他摄像头编号；关闭正在占用设备的应用，并检查设备权限。 |
| 选左目或右目后画面不符合预期 | 确认设备输出水平左右拼接帧，并检查完整画面；普通单幅画面选择左右目也会按宽度裁切。 |
| 视频打不开 | 检查文件路径与视频编码是否受本机 OpenCV / FFmpeg 支持。 |
| 推理速度较慢 | 使用较小模型或降低输入尺寸；可到「更多」准备 NVIDIA GPU 支持，再选择自动或 GPU；首次载入和预处理仍有开销。 |

模型、图像、推理及结果保存在本机。Python `.pt` 后端通过本地进程与 Qt 应用交换图像和预测，程序不会自动上传输入内容或推理结果。
