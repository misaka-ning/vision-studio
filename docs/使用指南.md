# Vision Studio 使用指南

本指南适用于 2.5.0；验收范围、实测结果和限制以同版证据为准，安装文件以 GitHub Releases 已发布版本为准。

## 从旧版本升级

正式发布后校验同版 `SHA256SUMS`，再使用 `sudo apt install ./vision-studio_2.5.0-1_amd64.deb`。包版本高于 2.4.0 和此前版本，可直接升级；先停止检测、评估、录像与转换，导出需要永久保存的结果，退出旧程序再安装。设置、运行记录、模型、导出、录像、评估报告与已有 GPU 环境保留。普通检测临时缓存不会跨重启保留；评估报告与预测快照独立保存在个人数据目录。升级后重新打开应用。

## 全局模型与结构显示

在「模型库」点击模型即可全局选用；「检测工作台」「模型显示」和「模型转换」默认来源使用这个模型。可拖动模型条目调整列表顺序，退出并重启后保留排序；拖动只改变位置，不改变当前全局选中的模型。「前往检测工作台」和「查看模型结构」只切换页面。导入模型也会同步更新全局模型。

右键任意模型条目可打开其位置、添加／修改备注、重命名显示名称或从列表移除。右键操作针对该条目，不自动切换全局模型。显示名称只改应用中的名称，原始文件名、路径、类别与权重不变，留空可恢复原始名称；备注可记录用途或实验说明，留空清除。名称和备注重启后保留。移除只删除列表项，原模型文件仍在磁盘；移除当前项会选择仍存在的模型，无可用模型时清空选择。

选择模型后，应用在后台异步解析并排列结构，完成后保留本次运行的图形缓存。进入或离开「模型显示」不会重复加载，原来的缩放、平移和节点详情也会保留。切换模型会加载新结构；格式不受支持或文件损坏时显示文字说明，可以点击「重试加载」。

在模型显示页切换「结构图」「层级树」「参数表」检查同一个模型。三种模式复用一次解析缓存，切换无需重新加载模型；使用搜索定位内容，再查看对应详情。结构图用于查看节点与连接，层级树用于浏览可解析的模块或权重分组，参数表用于集中核对参数与张量信息。图中嵌套对象和详情也使用深色背景与可读文字。

结构图使用 Netron 内置查找。层级树的搜索匹配名称、类型和路径，保留匹配项的祖先，便于沿层级定位；参数表可按路径、dtype、shape、元素数或备注查找。点击条目查看文件中可靠保存的元信息。表可包含权重、常量和缓冲，不代表可训练参数总量，也不统计运行激活。大型模型超出显示限额时会提示截断。选择新模型后旧搜索与详情会清除，当前模式保持不变。

结构由随包的 Netron 9.3.1 在本机显示。ONNX 展示文件内的运算图；普通 `.pt` 的包含关系、权重分组和静态信息不代表完整 forward，应用不会补造运算连接，也不会为查看结构执行 `torch.load`。所有非 ONNX 文件都会显示一行提示：

想看完整结构，建使用导出的 ONNX。

## 转换模型

「模型转换」位于左侧「录制视频」之后、「更多」之前，默认来源为模型库全局模型；点击「在模型库中选择」回到同一模型库。ONNX 来源会提示不支持，本版提供 PT → ONNX / TorchScript，不还原 ONNX 为原始训练检查点。

1. 在模型库选用受支持的现代 Ultralytics 检测／分类完整 PT、随附框架兼容的 YOLOv5 检测完整 PT，或有必要元数据的标准 TorchScript。TorchScript 需声明 `detect`／`classify` 任务与类别，通道须能从输入图可靠读取或在 `config.txt` 中声明。裸 `state_dict` 或缺少自定义类定义的模型不能直接重建。
2. 选择目标格式与正方形输入尺寸，尺寸范围 32–4096 px，须为 32 的倍数。通道按模型读取，C1 不强制变成 C3。
3. ONNX 选择 Opset 12（优先兼容 OpenCV）或 17（较新的算子集）；TorchScript 不使用 Opset。导出统一为 CPU FP32、batch=1、固定输入、不含 NMS，阈值与 NMS 仍在工作台设置。
4. 选择可写保存目录与名称。默认目录为个人数据目录的 `converted-models/`；ONNX 名称以 `.onnx` 结尾，TorchScript 以 `.torchscript` 结尾。已有文件或同名符号链接拒绝覆盖，请换名称。
5. 点击「开始转换」，查看后台阶段日志与进度；可「取消转换」。本次来源在开始时固定，切换全局模型不会改变正在执行的任务。取消通过后台进程停止完成，原模型与已有输出保留；如果完整文件已在取消请求前写出，界面会提示完成或保留该结果，请以最终状态为准。
6. 成功后点击「打开输出文件夹」，或明确点击「加入模型库」导入并选用结果。转换完成本身不替换全局模型；检测运行时需先结束检测再入库。应用记录转换元数据，再次选择该结果会应用任务、类别、输入尺寸及默认归一化，用户手工导入的标签仍优先。C1 自动选择灰度；C3 不自动判断是否用灰度训练，灰度训练应选择灰度，PT／TorchScript 彩色继续使用 RGB。建议用实际图片核对结果。

ONNX 保存任务、类别、输入形状和通道信息；TorchScript 归档包含 `config.txt`。导出以固定示例输入生成推理图，仅接受本项目约定的原始 YOLO 检测张量或单标签分类张量，未知动态控制流、自定义算子或训练功能不保证完整保留，不支持时显示错误。灰度按 C1 直接输入或 C3 复制三份相同亮度，左右目裁切仍在工作台设置。

为兼容随系统提供的 OpenCV 4.5，转换器对能够确定的静态形状、常量别名与广播做等价规约，输出仍是标准 ONNX。保存前会执行 ONNX 检查，并用两个固定测试输入比较转换环境的 Python OpenCV DNN 与原模型跟踪图的输出；检查失败时不提交转换文件。系统 C++ OpenCV、实际图片与 GPU 后端仍需分别验证，不能据此保证任意网络或算子都兼容。

转换使用随包 CPU Python / PyTorch 与 ONNX 1.17.0／protobuf 6.33.0，独立于工作台的 CPU／NVIDIA GPU 选择。完整 DEB 环境准备后可离线转换，不需要准备 GPU 支持；仅源码 checkout 需自行准备依赖。加载与转换 PT 均应使用可信文件。

## 完成第一次推理

1. 启动 Vision Studio，在「模型库」选用模型。工作台启动为空，不再自动载入示例图。
2. 导入自己的 `.onnx`、`.pt` 或兼容 `.torchscript` 模型。ONNX 检测模型选择 YOLOv5 或 YOLOv8 / YOLO11，分类模型选择图像分类。现代 Ultralytics `.pt` 使用模型自带的任务与类别信息；通过转换页加入库的结果应用已记录配置。
3. ONNX 自定义检测模型需导入标签文件。标签按类别 ID 顺序排列，每行一个类别，例如 `person`、`bicycle`、`car`，数量必须与输出类别数一致；默认检测标签为 COCO 80 类。`.pt` 自动读取类别名称，也可导入数量匹配的标签来覆盖名称。
4. 在顶部任务条选择「YOLO 数据集」「视频」或「摄像头」。图片检测统一从标准 YOLO 数据集导入，按配置中的集合建立队列；不再支持独立图片、普通图片文件夹或图片拖入。
5. 选择与模型训练一致的彩色或灰度输入，调整输入尺寸、置信度和 NMS 阈值，点击「开始检测」。
6. 查看结果，在「更多」中点击「导出结果」。批量完成后可点击队列中的图片，恢复该图片本轮检测的标注、目标列表和指标；手动导出保存当前选中图片的结果。需要逐张永久保存时，可启用自动导出。

## 数据集队列与批量回看

图片统一通过「YOLO 数据集」导入。集合目录、图片名单与列表的解析和顺序沿用数据集配置，不再提供无配置的普通图片文件夹扫描。队列没有固定50张限制；实际数量以数据集预检查后有效的图片为准。

队列条目按 GUI 事件循环分片加入。缩略图按可见项及附近范围在后台解码，不在导入时同步读取整集图片；选中原图、预处理后的预览与缓存叠加也在后台读取和构建。加载期间显示当前状态，快速换图、切换颜色或清空队列后，过期任务的返回结果不会覆盖新选择。已有有效预测仍按原缓存规则回看，后台加载不等于重新推理。实际响应与耗时受图片尺寸、磁盘和本机资源影响，不承诺固定速度。

在「开始检测」正上方选择「检测范围」，不弹出额外对话框：

| 模式 | 本次处理图片 |
| --- | --- |
| 检测当前集合（默认） | 仅处理当前选择的 Train／Val／Test 集合，按其队列顺序从第一张到最后一张，与当前选中图片无关 |
| 从当前图片向后检测 | 包含当前选中图片，依次到队列末尾 |
| 只检测当前图片 | 只处理当前选中图片，完成后结束任务 |

“当前图片”是输入队列中的选中项。后两种模式没有选中项时，行内显示提示且开始按钮不可用，不会改为全部检测。单张队列三种模式均最多处理这一张；选中最后一张时，向后检测也只处理一张。视频和摄像头不使用范围控件。

开始时固定本次范围与顺序，运行期间不可修改范围或编辑队列。行内显示例如“本次检测38张：第13～50张”，进度与完成数均以本次任务为准。尚未处理及范围外没有缓存的图片只显示原图，不会被标为已检测。

点击「停止运行」或按Esc后，不再调度下一张；当前CPU前向计算无法强行打断，但界面继续响应，不等待磁盘写入或保存队列。缓存、自动导出及运行记录在后台收尾；已交付结果仍可回看，写入完成后恢复下一任务入口。

检测完成或中断后，选择队列图片可恢复其标注、类别、置信度、目标表和指标。零匹配也是有效结果，关闭自动保存仍可回看。手动导出始终针对所选图片及其对应的检测配置。

同一模型与参数下重新检测，每张完成后再替换该图结果；停止前尚未重新处理的图片及范围外图片保留仍有效的缓存。修改模型、阈值、预处理、计算设备、标签映射或类别筛选时清除不兼容结果，避免显示旧配置预测。仅更改检测范围不会清除有效缓存。清空／更换来源、删除输入或关闭程序后不跨会话保留，永久保存请导出。

## 按类别 ID 筛选

「类别标签」仍只负责原始ID到名称的映射，标签文件依旧每行一个名称；不要通过删标签行或重排名称来筛选。

在独立的「类别筛选」中输入模型原始 class_id：

| 输入 | 效果 |
| --- | --- |
| 留空 | 保留全部类别 |
| `32` | 仅保留原始ID32 |
| `0,2,32` | 保留三个原始ID |
| `0， 2，32，32` 或 `0 2 32` | 中文逗号、空格可作分隔，重复ID自动去除 |

ID从0开始。负数、非整数、数值溢出及超出模型类别数量的输入均显示行内提示并阻止开始，不弹窗。模型选用后在后台读取其实际类别范围；非空筛选等待校验完成，切换模型后重新校验。用户标签行数和COCO默认80类不作为自定义模型范围的替代。无法确定类别数量时，先使用支持的元信息或重新导出模型，不会未经验证按80类接受输入。

筛选保留原始ID32，不会重新编号为0。ONNX CPU、ONNX CUDA、PT和TorchScript检测均执行筛选，预览框、目标列表、计数、自动保存、手动导出和视频录制使用同一过滤结果。没有匹配目标时保留图片和零目标结果，可回看、可导出。图像分类任务禁用此控件并显示原因。

筛选条件改变后旧结果失效；再次运行时仍遵循当前检测范围，不自动处理范围外图片。

**COCO类别系统中的ID32是sports ball**，涵盖足球、篮球等多种运动球。筛选该ID只选择模型已经给出的该类别预测，不会让模型变成只识别足球，也不会弥补训练数据或模型本身的漏检。自定义模型的ID含义以其自身类别定义为准。

## 在同一工作台评估与调优

「图像预览」用于观察模型在数据集图片、视频或摄像头上的结果；mAP、Precision、Recall 则需要正确的真实标注（GT）。工作台以「YOLO 数据集」作为图片入口，提供「图像预览」「评估与阈值」两个完整子页，继续使用模型库的全局模型。检测子页保留参数、画布、队列与目标列表，评估子页集中呈现指标、曲线、错例与报告。切换子页只切换查看位置，不修改任务配置或模式，不清空结果，也不自动开始或重复推理；点击对应的开始按钮才执行检测或评估。首版只评估一个目标类别，适用于单类足球模型，也可评估多类模型中选定的目标。

### 导入标准 YOLO 数据集

点击「YOLO 数据集」或按 Ctrl+O，使用同一个选择器导入现有数据集根文件夹或 `.yaml`／`.yml` 配置。单击文件夹后点击「导入此文件夹」直接导入，双击文件夹继续浏览；也可直接选中配置文件后确认。无需先选择输入类型，也没有独立箭头菜单。不存在的路径或其他文件类型会在选择器内提示，不关闭当前选择器。例如：

```text
my-dataset/
├── dataset.yaml
├── images/val/001.jpg
├── images/val/002.jpg
├── labels/val/001.txt
└── labels/val/002.txt
```

```yaml
path: .
train: images/train
val: images/val
test: images/test
names:
  0: football
```

选择文件夹时仅检查根目录，优先使用唯一的 `data.yaml`、`data.yml`、`dataset.yaml` 或 `dataset.yml`（大小写不敏感）。如果没有这些约定名称，但根目录只有一个 YAML，也可使用它。存在多个约定配置，或无约定名称且有多个 YAML 时，会要求在同一个导入选择器中明确选择配置文件；不会扫描子文件夹或把训练配置猜作数据集。没有配置时需先提供标准 YOLO YAML，只有 images／labels 文件夹不足以确定集合和类别。

`path` 相对 YAML 所在目录解析；Train／Val／Test 的路径相对 `path`。集合可为目录、图片名单 `.txt`，或这些路径的列表；目录递归读取，名单内路径相对名单文件。图片通过最后一层 `images/…` 映射到 `labels/…`，不接受重复图片。`names` 为从 0 开始的连续列表或映射；每行标签是 `class_id x_center y_center width height`，坐标归一化到 0～1，不支持分割／姿态标签。

默认使用 Val。在紧凑的数据集上下文条切换 Test／Train，再「重新检查」。首次导入失败时，待导入位置、集合及可选 metadata 会保留，错误显示在行内；例如数据集只提供 Train，应明确切换 Train 后重试，程序不会自动更换集合。若已导入有效数据集，另一次导入失败会恢复原数据集、队列与结果。通过文件夹入口导入时，若 YAML 的绝对 `path` 已失效，会将旧根目录内且原位置已不存在的集合／名单路径，按相同相对位置只读映射到所选文件夹；严格检查成功后才导入，并显示迁移提示。原位置仍存在或旧根目录之外的绝对路径保留原含义，直接选择 YAML 则始终严格使用原路径。配置文件与原数据不会被改写；其他路径错误仍需核对 `path` 和集合配置。

预检查显示有效、有框、空标签、缺标签与审核排除数量；这里的有框数量涵盖数据集所有类别，最终无目标统计按映射后的目标类计算。

- 有效的空 `.txt` 表示已标注的无目标图片；缺少 `.txt` 不等于无目标，必须补齐后才能评估。
- 非整数／越界类别、无效坐标、损坏图像或 EXIF 方向不是 1 的图像需先修正，保证图片与标签使用相同坐标系。
- 普通 YOLO 数据集不要求 metadata。需要时展开「数据集设置 → 高级参数」，点击「审核文件」选择 `metadata.csv`。单类足球审核数据可选提供该文件：保留 Small／Occluded／Blurred／No Ball 分组，严格过滤排除、待审核和未确认样本，校验审核状态与标签是否一致。
- 程序只读原数据与模型，不下载数据、不改标注；导入只做预检查和 GT 预览，不自动开始整集推理。

### 对齐目标类别并运行

顶部任务条集中放置输入源与计算设备；数据集导入后，下方只保留一行数据摘要、集合操作、校验状态与设置入口。点击「数据集设置」打开按钮附近的悬浮卡片，类别映射、可选 metadata 与扫描配置不占据工作台布局，不会挤小画布。再次点击按钮、点击卡片外部、按 Esc 或点击关闭按钮即可收起；调整窗口或切换页面时安全收起，任务运行时锁定设置。状态提示持续显示在上下文条，点击可查看完整错误；长错误可滚动和复制，不会绕过校验启动。

在模型库选择受支持的检测模型，等待实际类别信息加载。打开「数据集设置」，填写「模型原始 ID → 数据集 ID」，界面显示双方名称。例如 COCO 模型 `32: sports ball → 0: football`；单类自训练模型通常是 `0 → 0`，仍应按实际定义确认。

映射只决定如何评估，不改变模型类别 ID、数据集标注或原有类别标签文件；常规「类别标签」负责名称，「类别筛选」负责日常检测结果，评估则使用独立的单目标映射。sports ball 包含多种球类，映射为 football 不会让 COCO 模型只识别足球。

1. 「图像预览」可先检查原图、GT 与预测是否对齐；「显示 GT」可切换叠加。尚未推理的 GT 仅为标注预览，不计作 FN。
2. 进入「评估与阈值」子页，检查并沿用当前模型、输入尺寸、颜色、灰度、NMS 和 CPU／NVIDIA GPU；切页本身不会发起任务。评估固定使用完整图片坐标，灰度按模型 C1／C3 约定输入，不裁切左目或右目。
3. 打开「数据集设置」，在其中的「高级参数」设置 GT 匹配 IoU（默认 0.5）和阈值扫描范围。匹配 IoU 与工作台 NMS IoU 用途不同：前者判断预测是否命中 GT，后者去除重复预测框。
4. 选择现有三种范围后点击「开始评估」。「检测当前集合」按当前选择的 Train／Val／Test 集合队列顺序评估，不合并其他集合；从当前向后只评估后缀；只检测当前图片用于单图对照。没有 50 张上限，范围与顺序在开始时固定，运行中锁定相关配置与队列编辑。
5. 评估在后台推理一次，使用最低置信度 0.001、固定每图最多 300 个 NMS 后候选及 30000 个 NMS 前候选上限。之后改变分析阈值可以复用缓存；模型、输入尺寸、颜色、预处理、NMS 或数据改变后需要重新评估。

停止会立即停止调度后续图片，界面继续响应；当前 ONNX CPU forward 仍可能需要结束。已完成前缀在后台保存为中断报告，未完成图片与范围外图片只显示 GT 预览，不会被计为已检测或漏检。计算指标、导出曲线也在后台完成，收尾结束后可开始下一任务。

### 正确理解指标与范围

| 指标 | 口径 |
| --- | --- |
| mAP50／mAP50–95 | 所选目标类在 IoU 0.50，及 0.50～0.95、步长 0.05 上的 AP；首版不是所有类别的总体 mAP |
| Precision | TP／(TP＋FP)，对应当前分析置信度 |
| Recall | TP／(TP＋FN)，对应当前分析置信度与 GT 匹配 IoU |
| F1 | 2TP／(2TP＋FP＋FN) |
| 无目标图片误报率 | 至少出现一个目标误报的确认无目标图片数／全部确认无目标图片数 |

TP 是与目标 GT 成功一对一匹配的预测，FP 是未匹配预测（包括重复框），FN 是未匹配目标 GT。匹配按最高 IoU，平局按预测与 GT 的原始顺序稳定处理；过滤置信度后重新匹配。非目标类别的 GT 不参与此目标类匹配，含其他类别而不含目标类的图片也属于该目标的负样本。

AP 使用低分候选，不随当前分析阈值变化；P／R／F1 和误报率随阈值更新。没有目标 GT 时 Recall／AP 为 N/A，没有负样本时无目标误报率为 N/A。没有预测但有 GT 时 P／R／F1 为 0；预测和 GT 均为空时未定义的指标为 N/A。

完整完成且超过一张图片的集合才显示主 AP。单图、子集及中断任务明确标记范围，主 AP 为 N/A；导出中的 `partial_metrics` 可以保留描述性 AP，不能当作完整集合成绩。选择 Train 只观察拟合情况；Test 应用于固定配置后的验证。

### 分析阈值、回看错例与采用配置

进入工作台「评估与阈值」子页，以完整工作区查看指标卡、交互曲线和阈值表。默认扫描 0.05～0.95、步长 0.01，共 91 个工作点；可在开始前修改。鼠标悬停读取数值，点击曲线／表格或调整「分析阈值」选择已有工作点，非扫描点会吸附到最近的实际工作点，不重复推理。

「全部图片／包含误检／包含漏检／无目标图片误报」只筛选当前查看的已完成样本，不改变原任务范围。选择图片后回到「图像预览」子页的画布查看 GT、TP／FP／FN 和目标列表；更改分析阈值后指标、错例与叠加同步更新。无匹配图片时显示空状态，不借用旧结果。

仅完整 Val 集可使用「均衡 · F1 最大」「最低 Precision 下的最大 Recall」「最高误报率下的最大 Recall」查看推荐。条件不可满足时显示无可行点，不自动放宽；Test、Train、子集和中断任务只作描述性分析。

浏览曲线与「查看推荐工作点」不会改变日常检测参数。明确点击「采用检测配置」，才将报告中的输入尺寸、颜色、预处理、NMS、设备、模型原始类别及当前选定置信度应用到工作台；程序会核对全局模型内容与报告一致。然后切回「图像预览」，可在数据集队列、视频或摄像头上点击「开始检测」使用该配置。工作台置信度支持 0.001～1.000、三位小数，采用时保留扫描工作点精度。原始评估报告与成绩保持不变，模型库记录对应报告与已采用阈值。

### 保存与重新打开评估

结果位于个人数据目录的 `evaluations/<任务ID>/`，包含任务状态、固定配置、数据与模型哈希、标注与低分预测快照、逐图结果、阈值 CSV、错例 CSV、Markdown 报告和深色 PNG／SVG 曲线。普通检测缓存仍是临时的，评估报告则可跨重启回看。

在「运行记录」双击评估记录，或在模型库点击「查看评估 / 检测配置」，可重新打开对应报告。历史数值与标注使用当时快照，不要求重新载入原模型；图像叠加还需原图存在且哈希相符。原图移动、内容改变或缓存损坏时提示原因，保留数值，不将旧预测画到新图上。

「打开保存文件夹」进入本次评估目录；「打开报告」查看 Markdown；「导出原始评估报告」复制完整报告及缓存，并额外保存 `analysis-selection.json` 记录导出时的阈值与工作点，原始扫描表和报告不改写。单图 PNG／JSON／CSV 导出仍对应当前选中图片与分析阈值，JSON 额外记录 GT、匹配与评估来源。

本版没有模型训练、多类总体 mAP、分类评估、左右目／ROI 裁剪评估、NMS IoU 二维扫描及视频／摄像头在线 mAP。视频录像仍可供人工观察，不能凭未标注画面得出 AP 或准确率。

## 计算设备与 GPU 准备

在工作台选择「自动 · 优先 NVIDIA GPU」「CPU」或「NVIDIA GPU」，多卡电脑可选择 GPU 编号。自动模式优先使用已准备的 GPU，无法使用时说明原因并使用 CPU；显式 GPU 模式失败时给出错误，避免把 CPU 结果当作 GPU 结果。运行期间锁定设备选项，切换设备后需重新载入模型。状态和导出的设备字段记录实际执行设备。

首次使用 NVIDIA GPU，进入「更多」点击「检查 GPU 环境」。检测到显卡不代表推理依赖已准备；点击「准备 GPU 支持」从官方源下载约 4–5 GB，建议预留至少 20 GB 空间。进度条和日志显示准备阶段，可以点击「取消准备」。下载、校验或实际 CUDA 自检失败时报告原因，并保留原来的 CPU／已就绪 GPU 环境。

GPU 依赖安装至个人数据目录的 `gpu-runtime/`，与 `/opt/VisionStudio/runtime` 中的 CPU／Netron 环境独立。不修改显卡驱动，也不需要全局 CUDA Toolkit。正式 DEB 声明系统 Python 3.10 venv 依赖，APT 安装时不会自动下载 GPU wheel；GPU 初次配置完成后可离线推理。推荐 Linux NVIDIA 驱动 ≥ 570.26；显存不足、算子不支持或 GPU 不可用时可改选 CPU。TensorRT、AMD、Intel GPU 尚未支持。

命令行配置与只读检查：

```bash
/opt/VisionStudio/scripts/setup_gpu.sh
/usr/bin/python3.10 /opt/VisionStudio/scripts/gpu_probe.py
```

源码目录使用 `./scripts/setup_gpu.sh` 和 `/usr/bin/python3.10 scripts/gpu_probe.py`。默认明确使用系统 Python 3.10，避免 PATH 中不兼容的 Conda 解释器。可指定 `--runtime-dir /用户专用目录/gpu-runtime`，并在启动应用前设置 `VISION_STUDIO_GPU_RUNTIME_DIR` 为同一绝对路径；未知内容或符号链接目录会拒绝安装。

CPU ONNX 使用 C++ OpenCV DNN；GPU ONNX 使用 C++ ONNX Runtime 1.23.2 CUDA。PT 三类受支持的模型均通过本地 PyTorch 执行，GPU 环境为 `2.9.1+cu128`。颜色、灰度 C1／C3、左右目及后处理设置在不同设备上保持一致。Netron 可视化继续使用 CPU 环境，与计算设备选择无关。

## 选择模型参数

ONNX 在 C++ OpenCV（CPU）或 ONNX Runtime（GPU）中执行；`.pt` 由本机独立 PyTorch runtime 执行，界面仍为 C++ / Qt。工作台会显示所用后端。

**输入尺寸**是模型接收的正方形图像宽高。例如模型导出为 640 × 640，则填写 640。动态尺寸模型也需确认模型允许选择的尺寸。固定尺寸模型填错可能导致推理失败。

**置信度阈值**过滤低分目标。调低可显示更多候选目标，也可能增加误检。**NMS 阈值**控制同类别检测框的重叠抑制；数值越低，重叠框越容易被合并。不同类别的框会保留。

输入尺寸、置信度与 NMS IoU 控件不接受鼠标滚轮改值，避免滚动页面时误改参数。需要调整时，直接输入数值、使用键盘或点击控件的步进按钮；画布上的滚轮仍用于缩放图像。

**RGB 通道、缩放系数和均值**需与模型训练及导出时的预处理一致。常见 YOLO 模型使用 RGB、系数 `1 / 255`、均值 0。分类模型可能采用其他均值或缩放方式，应以模型说明为准。当前界面支持统一缩放系数及各通道均值，暂未提供各通道标准差设置。

上述手工预处理适用于 ONNX。现代 YOLO `.pt` 使用 Ultralytics 的原生图像预处理与 NMS；保留默认 RGB、`1 / 255` 和零均值配置。应用会拒绝不受支持的 `.pt` 手工预处理，避免参数被静默忽略。

## 使用灰度 ONNX 模型

在工作台选择「灰度」输入模式。应用从 ONNX 的 NCHW 图像输入解析通道数：`[1,1,H,W]` 接收单通道灰度，`[1,3,H,W]` 接收三份相同的灰度值。彩色输入按亮度权重转换为 8 位灰度，随后执行缩放、补边和模型所需的归一化。

灰度模式只使用一个均值（原 R 均值）；缩放计算为 `(灰度值 - 均值) × 缩放系数`。三通道灰度统一使用该均值，G / B 均值配置不参与，RGB / BGR 切换不会改变灰度值。检测仍保持比例并用 114 补边，分类仍缩放到正方形。

模型输入通道数自动解析，不需要把图片手工改成灰度文件。灰度推理后的画布和 PNG 标注底图显示实际灰度，仍保持所选画面的尺寸。切回 RGB / BGR 后恢复原色，旧检测框、目标列表和指标会清除，需重新运行后再导出。

默认仍为彩色，旧版保存的设置继续使用彩色。单通道模型若选择彩色会提示改用灰度。当前 ONNX 仅支持固定的 1 或 3 通道；动态通道、4 通道、多个运行时图像输入和非四维 NCHW 输入需重新导出为兼容模型。动态宽高的算子兼容性仍由 OpenCV 决定。

选择灰度不会把彩色训练的模型自动变成灰度模型；应使用训练时相同的颜色转换和归一化。

## 使用单设备左右拼接摄像头或视频

选择对应摄像头编号或打开视频，在画面选择中使用「完整画面」「左目」或「右目」。这适用于一个设备输出左右水平拼接画面的情况。应用保留摄像头默认分辨率，实际裁切尺寸由采集到的源帧决定。

| 画面选择 | 推理图像 |
| --- | --- |
| 完整画面 | 原始整帧 |
| 左目 | 从最左列开始取 `floor(原始宽度 / 2)` 列 |
| 右目 | 从上述分界列开始取剩余列，奇数宽度时比左目多一列 |

例如 1280 × 480 的拼接帧，左目与右目各为 640 × 480；宽度 129 的帧分别得到宽度 64 和 65。裁切在模型预处理之前完成，之后按彩色 / 灰度和输入尺寸设置执行推理。

工作台预览、检测框坐标和 PNG 标注都以所选画面为准。右目的 `x=0` 是右目画面的左边界。JSON 保存画面选择与原始帧尺寸，便于追溯来源。视频或摄像头结束后的自动导出仍使用最后一帧。图片队列保持完整图像，即使上次摄像头选择了左目或右目，也不会裁切图片。

ONNX 检测图像会保持比例缩放并补边；ONNX 分类图像会直接缩放至正方形。分类输出若为 logits，应用进行 softmax 后显示概率；若已是归一化概率，则保留原值。分类显示概率最高的 5 个类别（类别少于 5 个时全部显示），置信度与 NMS 阈值用于检测任务。Ultralytics `.pt` 与兼容的 TorchScript 分类均采用 Ultralytics 标准分类图像变换，以 PIL RGB 图像输入 `classify_transforms`；模型需与该预处理匹配。

## 使用 .pt 检查点

选择自己训练或可信来源的现代 Ultralytics YOLOv8 / YOLO11 `.pt`，直接导入并运行。完整检查点提供模型架构和类别信息；只有 `state_dict` 的权重字典需要额外架构，不能直接作为完整模型使用。

标准 YOLOv5 完整检查点由随附的 `vendor/yolov5` v7.0 兼容框架加载，`models/yolov5n.pt` 为真实示例。训练时新增的自定义模块仍需要原项目代码。TorchScript `.pt`／`.torchscript` 需提供任务、类别名称元数据，并具有标准原始检测输出或单标签分类输出。

现代 Ultralytics、兼容 YOLOv5 与标准 TorchScript 的 1 / 3 通道模型可选择灰度输入。通道数从实际模型输入层读取；TorchScript 无法可靠识别输入层时，应在导出归档内的 `config.txt` JSON 对象中加入 `"input_channels": 1` 或 `"input_channels": 3`。声明与模型输入层冲突会报错。彩色模式要求 3 通道。

`.pt` 灰度检测先按亮度转换，单通道模型接收一个通道，三通道模型接收三份灰度；随后 letterbox、除以 255 并使用模型后处理。`.pt` 检测的输入尺寸须为 32 的倍数，否则载入时会提示调整尺寸。灰度分类使用 Ultralytics 分类图像变换，明确设定所有通道 `mean=0`、`std=1`，再按模型通道数输入。手工 ONNX 均值和缩放不用于 `.pt`；保留缩放 `1 / 255`、零均值，灰度不受 RGB / BGR 切换影响。

`.pt` 第一次加载需要启动 Python 并载入 PyTorch。后续图片与视频帧复用同一后台模型。正式 DEB 和本机主文件夹中的安装已包含独立 CPU `runtime`。早期 `scripts/package.sh` 生成的便携目录不携带此环境，需要准备 Python 3.10 或 3.11，在该目录先运行 `./scripts/setup_pt.sh` 下载并安装锁定版本的依赖。准备完成后推理可离线执行。使用其他解释器时，在启动前将 `VISION_STUDIO_PYTHON` 设置为其绝对路径，并确认其中安装了相应版本的依赖锁。

PyTorch 检查点载入可能通过 pickle 执行 Python 代码，应使用自己训练或来源可信的文件。

## 查看图像和结果

中央画布展示所选画面和预测，彩色 / 灰度显示与输入模式一致。适应视图让整张图像可见；缩放和拖动画布便于检查细节。显示检测框、显示标签可独立切换。右侧目标表记录类别、置信度与位置。

| 画布操作 | 作用 |
| --- | --- |
| 滚轮 | 以鼠标位置为中心缩放 |
| 鼠标拖动 | 平移图像 |
| 双击，或按 `F` / `0` | 适应视图 |
| 按 `1` | 原始尺寸 |
| 按 `+` / `-` | 放大 / 缩小 |
| 方向键 | 平移图像 |
| 点击检测框 | 定位到对应预测 |
| 按 `Esc` | 取消画布选择 |

键盘操作需要画布获得焦点，可先点击图像。

「推理耗时」只衡量模型 forward；总耗时还包含图像预处理和结果解码。视频与摄像头以逐帧方式处理，实际速度取决于所选 CPU／GPU、输入尺寸与模型规模。UI 更新和导出也会增加运行开销。

推理期间可以点击「停止运行」。ONNX CPU 的当前 OpenCV forward 不能强制中断，会在该次调用完成后停止；推理在工作线程中执行，界面继续响应，不再处理后续图片。ONNX CUDA 向 ONNX Runtime 发出终止请求；`.pt` 会终止后台推理进程，随后可重新加载模型。停止不等待后台结果写入，已接受的缓存／自动导出／运行记录完成后恢复下一任务按钮。关闭窗口时异步等待工作线程和这些写入收尾，不在主线程阻塞。

## 录制与查看标注视频

1. 在工作台选择视频或摄像头，设置完整 / 左目 / 右目及彩色 / 灰度，点击「开始检测」。图片队列不提供录制。
2. 推理期间点击「开始录制」，按钮变为「结束录制」。录制保存所选画面的实际颜色模式，并叠加检测框、标签和置信度。
3. 点击「结束录制」完成当前录像，推理可以继续。等待「正在保存…」结束后，在「录制视频」页查看文件。源视频结束、停止推理或退出时会收尾当前录像。
4. 在列表选择录像，点击「播放录像」或「暂停播放」检查结果；可以刷新列表、打开录像文件夹或导出录像。

默认文件位于用户数据目录的 `recordings/`，每次录制产生 MJPEG `.avi` 与同名 `.json`。元数据记录帧数、帧率、时长、内容及编码尺寸、颜色模式、所选眼、源帧尺寸、模型和来源。文件在写入器关闭并校验后才显示为已完成录像。录制只包含已处理的图像帧，不包含音频。

录像覆盖每个实际推理帧，不受工作台预览刷新节流影响。视频文件使用来源帧率；摄像头按实际录制时长确定播放帧率，保留处理到的全部帧。为了兼容 MJPEG，奇数宽高会在右侧或底部复制一行 / 列补为偶数，元数据保留实际内容尺寸，应用播放时裁回内容画面。

## 导出与运行记录

导出结果包含带叠加标注的 PNG、JSON 和 CSV。手动导出入口位于「更多」，原有导出快捷键仍可使用。PNG 使用当前所选图像尺寸与颜色模式绘制完整检测框与标签；分类 PNG 展示概率最高的类别。JSON 记录 `source`、`model`、`task`、`backend`、`requested_device`、`actual_device`、`device_index`、`device_name`、`device_notice`、图像宽高、帧号、推理与总耗时及 `predictions`；`config.color_mode` 和 `config.input_channels` 保存模型输入模式及通道数，`stereo_view` 与 `source_frame_size` 保存画面选择和原始帧尺寸。每个预测包含 `class_id`、`label`、`confidence`、`x`、`y`、`width`、`height`。检测坐标相对所选图像；图片与完整画面对应原图，左右目对应所选眼图。CSV 为每个预测保存一行，适合在表格工具中进一步分析。分类任务的位置字段为 0。

空检测结果也属于有效结果，意味着当前参数下没有目标超过阈值，仍可回看和导出。图片队列保存已完成图片的本轮结果，回看不会重新推理、追加运行记录或重复自动导出；未处理的图片仍只显示原图。结果缓存只用于当前会话；同配置的新任务逐图更新结果，停止不会提前抹除有效旧结果。清空队列、变更模型／推理参数／颜色模式／计算设备／类别筛选或关闭程序时释放不兼容缓存，永久保存仍需导出。

自动保存每张图片的选项下方提供「打开保存文件夹」入口，打开实际自动导出目录，便于查看生成的 PNG、JSON 和 CSV。尚未生成结果时目录可以为空；更改导出位置后，该入口同步指向新目录。

自动导出会逐张保存数据集图片检测队列的结果；视频与摄像头在任务结束后保存最后一帧。需要连续标注视频时，可在视频或摄像头推理期间使用「开始录制」，录像在「录制视频」页查看。运行记录提供最近 200 次检测或评估摘要；双击评估记录重开持久报告，普通检测的完整图像与预测应通过导出保存。

## 输入方式与快捷键

2.5.0 的公开输入方式为标准 YOLO 数据集、视频和摄像头。普通图片／图片文件夹按钮、图片拖入、「更多」运行示例及 `--demo`／`--pt-demo` 已移除；它们不会藏到其他页面继续导入。已有评估报告与运行记录仍可查看。

| 快捷键 | 操作 |
| --- | --- |
| Ctrl+O | 在同一选择器导入 YOLO 数据集文件夹或 YAML 配置 |
| Ctrl+M | 导入模型 |
| Ctrl+R | 开始当前任务 |
| Ctrl+E | 导出当前结果 |
| Esc | 停止当前任务（数据集设置悬浮卡片打开时，Esc 优先关闭卡片） |

画布继续支持滚轮缩放、拖动平移、双击适应、F 适应视图与 1 原始尺寸；这些画布操作不导入图片。`--smoke`、`--smoke-pt` 等选项仅用于开发和发行验收，保留内部真实模型检查，不是新的普通图片入口。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| ONNX 模型加载失败 | 确认文件存在，核对当前实际后端、输入输出约定及其算子支持。 |
| 检测到显卡但 GPU 不可用 | 到「更多」准备依赖并检查环境；`nvidia-smi` 的 CUDA Version 只是驱动支持上限。 |
| GPU 准备失败／被取消 | 查看日志，保留 CPU 使用；检查网络和剩余空间后重试。未知目录需要换专用目录。 |
| GPU 显存不足 | 选择较小模型、减小输入或改选 CPU；显式 GPU 模式会报告错误。 |
| 提示单通道模型需要灰度 | 选择「灰度」输入模式，并核对训练时的预处理。 |
| 提示 ONNX 通道无法确定或不支持 | 导出固定 1 / 3 通道的四维 NCHW、单运行时图像输入模型；动态宽高和通道数是不同设置。 |
| `.pt` 提示 Python 不存在 | 检查交付目录的 `runtime/bin/python`，或修正 `VISION_STUDIO_PYTHON`。 |
| `.pt` 提示只有 state_dict | 提供包含模型架构的完整 Ultralytics 检查点；仅有权重字典无法确定网络结构。 |
| `.pt` 提示缺少模块或模型类 | 检查 runtime 依赖，并确认检查点来自受支持的现代 Ultralytics YOLO。 |
| 输出维度不匹配 | 核对任务类型；重新导出不带 NMS 的原始检测输出。 |
| 检测框位置不对 | 确认输出是中心点加宽高，坐标以模型输入像素为单位。 |
| 类别名称不对 | 标签文件应与训练类别顺序一致，不能仅按字母排序。 |
| 结果为空 | 检查图像内容、阈值、任务类型和预处理配置。 |
| 分类结果异常 | 检查输入尺寸、RGB / BGR、缩放系数和均值。带各通道标准差的预处理需由模型自身实现。 |
| 摄像头打不开 | 尝试其他摄像头编号；关闭正在占用设备的应用，并检查设备权限。 |
| 选左目或右目后画面不符合预期 | 确认设备输出水平左右拼接帧，并检查完整画面；普通单幅画面选择左右目也会按宽度裁切。 |
| 视频打不开 | 检查文件路径与视频编码是否受本机 OpenCV / FFmpeg 支持。 |
| 推理速度较慢 | 使用较小模型或降低输入尺寸；可到「更多」准备 NVIDIA GPU 支持，再选择自动或 GPU；首次载入和预处理仍有开销。 |

模型、图像、推理及结果保存在本机。Python `.pt` 后端通过本地进程与 Qt 应用交换图像和预测，程序不会自动上传输入内容或推理结果。
