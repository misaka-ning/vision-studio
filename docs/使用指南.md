# Vision Studio 使用指南

Vision Studio 在本机完成模型推理、标注数据集评估、阈值分析、模型结构查看与转换。本指南按操作顺序说明；逐版变化、安装命令和真实验收范围分别见[更新日志](../CHANGELOG.md)、[README](../README.md)和[发行说明](releases/)。

## 先认识工作空间

| 页面 | 用途 |
| --- | --- |
| 检测工作台 → 图像预览 | 选择输入、调整检测配置，查看原图、GT 与预测，处理视频或摄像头 |
| 检测工作台 → 评估与阈值 | 用带标注数据集计算目标类指标、比较阈值、浏览错例 |
| 模型库 | 全局选用模型，管理顺序、显示名称、备注和评估记录 |
| 模型显示 | 查看当前模型的结构图、层级树、参数表与可用的 YOLO YAML |
| 运行记录 | 查看任务摘要，重新打开已保存的评估报告 |
| 录制视频 | 播放、定位与导出已完成的标注录像 |
| 模型转换 | 将受支持的 PT 导出为 ONNX 或 TorchScript |
| 使用指南 | 本机内置操作说明，位于「更多」上方 |
| 更多 | 数据集启动恢复设置、GPU 环境管理和手动结果导出 |

「图像预览」和「评估与阈值」共用模型与输入。切换子页只改变查看位置，不开始任务、不采用推荐阈值，也不清空结果。日常检测可使用无标注图片；Precision、Recall 和 AP 必须使用正确的真实标注（GT）。

## 1. 选模型，完成第一次检测

1. 在「模型库」导入并选用可信的 `.onnx`、完整 `.pt` 或兼容 `.torchscript`。该选择全局生效，工作台、模型显示和转换页默认来源保持一致。
2. 在「图像预览」点击「YOLO 数据集」「视频」或「摄像头」。也可向预览区拖入数据集目录／YAML、一个视频或单张／多张图片。
3. 核对任务、实际类别、输入尺寸和训练预处理。ONNX 检测需选择匹配的 YOLO 输出格式；分类选择图像分类。自定义标签文件每行一个名称，严格对应原始 ID 顺序。
4. 选择 CPU、自动或 NVIDIA GPU，按需设置颜色、置信度、NMS IoU 和类别筛选。图片任务再选择检测范围，点击「开始检测」。
5. 完成或停止后，点击队列图片回看标注、目标表与指标；「更多 → 导出结果」保存当前选中图片。

输入尺寸、置信度和 NMS IoU 不接受滚轮改值，可直接输入、使用键盘或点击步进按钮。画布滚轮仍用于缩放。

| 模型类型 | 使用要点 |
| --- | --- |
| ONNX 检测 | 原始 YOLOv5 `[1,N,5+C]` 或 YOLOv8／YOLO11 `[1,4+C,N]` 输出；batch=1、FP32、不含 NMS，尺寸与实际输入一致 |
| 现代 Ultralytics PT | 完整检测／分类检查点，自动读取任务与类别，使用本地 PyTorch |
| YOLOv5 PT | 兼容随附 YOLOv5 v7.0 框架的完整检查点；自定义模块仍需原项目定义 |
| TorchScript | 兼容的原始检测／单标签分类输出，以及任务、类别和必要的通道元数据 |
| 图像分类 | 显示最高五类（不足五类则全部），不使用检测 NMS、类别筛选或目标检测评估 |

裸 `state_dict` 无法单独重建网络；分割、姿态、旋转框、未知端到端输出或自定义算子不保证兼容。PT 载入可能执行检查点中的 Python 代码，请只运行可信文件。详细约定见[模型说明](模型说明.md)。

点击模型条目全局选用，拖动调整顺序；右键可打开位置、编辑备注、重命名显示名称或从列表移除。重命名不改磁盘文件，移除也保留原文件。名称、备注、排序与选用状态会保存；右键操作本身不切换全局模型。

## 2. 导入数据集或临时输入

### 标准 YOLO 数据集

点击「YOLO 数据集」或按 `Ctrl+O`，在同一个选择器中选文件夹或 `.yaml`／`.yml`。单击目录后点击「导入此文件夹」，双击继续浏览。也可拖入相同目录或配置。

```text
my-dataset/
├── dataset.yaml
├── images/val/001.jpg
├── images/val/002.jpg
├── labels/val/001.txt
└── labels/val/002.txt
```

```yaml
path: .
val: images/val
names:
  0: football
```

文件夹入口优先识别根目录唯一的 `data.yaml`、`data.yml`、`dataset.yaml` 或 `dataset.yml`；无约定名称时接受根目录唯一的 YAML。有歧义需明确选文件。只有 `images/labels` 而无配置，不足以确定集合和类别。

`path` 相对 YAML 所在目录；Train／Val／Test 相对 `path`。集合支持目录、图片名单 `.txt` 或其列表，名单内路径相对名单文件。标签由最后一层 `images/…` 对应到 `labels/…`，每行采用 `class_id x_center y_center width height`，坐标归一化到 0～1，类别从 0 连续定义。不支持分割／姿态标签。

默认 Val；只有 Train 的数据集需切换 Train 后「重新检查」。文件夹导入可对已失效旧根目录做受限、只读的相对位置迁移，界面会说明；直接选 YAML 严格使用配置路径。导入不改写配置、图片或标注。

后台检查后分片建立队列，缩略图只解码可见及邻近项目，选中原图也异步加载，没有固定 50 张上限。摘要显示有效、有框、空标签、缺标签和排除数量。错误坐标／类别、损坏图片或非标准 EXIF 方向需先修正。**有效空标签是已标注无目标，缺标签不等于无目标**，后者不能直接评估。

「数据集设置」打开悬浮卡片，不占画布高度。再次点击按钮、点击外部、按 Esc 或关闭按钮即可收起。这里设置目标类别映射；「高级参数」提供匹配 IoU、阈值扫描和可选 `metadata.csv` 审核文件，标准 YOLO 数据集不要求 metadata。

### 拖入图片与视频

| 拖入内容 | 结果 |
| --- | --- |
| 一个数据集目录或 YAML／YML | 标准数据集导入，保留 GT 与评估能力 |
| 一个视频 | 切换为视频输入，不自动开始检测 |
| 单张／多张图片 | 保留拖入顺序，按规范本地路径去重，后台检查后建立临时队列 |
| 类型混合、多个视频／数据集、网络 URL 或未知格式 | 整批拒绝，显示说明 |

已有有效数据集时拖入图片，会询问「替换整个数据集」「临时加入」或「取消」，默认取消。替换只改变当前输入；临时加入追加到原队列，保留原 GT、有效结果和报告。两者都不修改原文件或最后成功数据集记录。

临时图片没有 GT，只参与检测，**不当作负样本或评估样本**，不跨重启恢复。未完成追加被停止时撤销本次新增项。运行、导入、转换或保存等忙状态拒绝新的拖入，应先结束当前操作。

### 记住数据集与启动恢复

完整成功导入后，程序原子写入个人数据目录的 `dataset-session.json`，记录原始文件夹／YAML 路径、集合和可选审核文件，不包含图片、标注或模型内容。

「更多 → 启动时恢复上次数据集」**默认开启**。普通启动后台重新检查磁盘数据，再恢复队列、GT 与首图；不自动检测、评估或恢复旧预测。关闭仅影响下次启动，当前数据与 JSON 记录保留，手动成功导入仍更新记录；重新开启从下次启动生效，不立即载入。此设置不会设置系统开机自启。

手动选择、清空和停止优先于待执行恢复。导入失败、停止或保存失败保留旧记录；清空队列、切换视频／摄像头或查看历史报告不覆盖记录。JSON 损坏或路径失效时行内提示，可手动重新导入，不修改原数据。

## 3. 检测范围、类别筛选与结果回看

开始按钮上方的范围在启动时固定图片和顺序：

| 范围 | 本次处理 |
| --- | --- |
| 检测当前集合（默认） | 队列首张至末张，与当前选择无关，包含临时追加项 |
| 从当前图片向后检测 | 包含所选图片，依次至末尾 |
| 只检测当前图片 | 仅所选图片，完成后结束 |

后两项必须先选图，否则行内提示且不可开始。进度与完成数只对应本次范围；运行期间锁定范围与输入。视频／摄像头不使用图片范围。

「停止运行」或 Esc 不再调度下一张，界面保持响应。当前 ONNX CPU forward 需结束，CUDA 请求终止，PT 停止后台进程；已接受的结果和磁盘写入在后台收尾，之后可开始下一任务。

完成或中断后，点击队列可回看标注、目标表与指标，包括零目标结果，不重复推理或自动保存。同模型与配置重测时逐张替换已完成结果，范围外有效缓存保留。修改模型、设备、推理参数、颜色、标签映射或类别筛选会清除不兼容缓存；仅改范围不会。普通缓存不跨重启，需永久保留请导出。

「类别标签」只映射名称；独立的「类别筛选」选择模型原始 ID，不删改标签行：

- 留空：全部类别。
- `32`：仅原始 ID 32。
- `0,2,32`、`0，2，32` 或 `0 2 32`：多个 ID，自动去重。

负数、非整数、溢出或超出当前模型实际类别范围时行内提示并阻止开始；切模型重新校验，不固定假设 80 类。筛选不重编号，预览、目标表、计数、自动保存、导出与录像使用同一结果；分类禁用此控件。

**COCO ID 32 是 sports ball，包含多种运动球，筛选它不等于只识别足球。** 自训练模型以自身类别定义为准。

## 4. 评估模型并选择阈值

### 运行有效评估

1. 导入带完整、正确标签的数据集，选择检测模型，等待实际类别就绪。
2. 在「数据集设置」核对「模型原始 ID → 数据集 ID」及双方名称。例如 COCO `32: sports ball → 0: football`；单类模型通常 `0 → 0`，仍需确认。映射只用于评估，不改模型 ID 或 GT。
3. 在「图像预览」核对原图与 GT。「显示 GT」切换标注；只有 GT、未推理的图片不算漏检。
4. 进入「评估与阈值」，核对模型、输入、颜色、预处理、设备与 NMS。评估使用完整图像，不裁左右目。
5. 在「数据集设置 → 高级参数」调整 GT 匹配 IoU 与扫描范围，选择任务范围后「开始评估」。匹配 IoU 判断命中，NMS IoU 去重，两者不同。

评估针对**映射的一种目标类别**，不是多类总体 mAP。全范围仅含原标注集合，后缀只到原集合末尾，单图仅接受原数据集项。选中临时图片时，后缀／单图评估禁用并说明原因。

后台推理一次采集低分候选：默认最低置信度 0.001、每图最多 300 个 NMS 后候选；这两项可在高级参数调整，NMS 前上限仍为 30000。采集下限不能高于分析置信度或扫描起点，否则所需候选已经丢失。PT 可选真实 batch 1～32，尾批按原顺序；ONNX／TorchScript 实际单张执行并在报告说明。CPU 线程数 0 为自动，非零只适用于 PT 常驻子进程；ONNX 请使用自动。阈值分析复用缓存；更换模型、尺寸、预处理、NMS 或数据后应重新评估。停止后保存已完成前缀为中断报告，未完成与范围外图片不计漏检。

### 正确理解报告

| 指标 | 口径 |
| --- | --- |
| mAP50／mAP50–95 | 映射目标类在 IoU 0.50，以及 0.50～0.95、步长 0.05 上的 AP |
| Precision／Recall／F1 | 当前分析置信度与匹配 IoU 下的精确率、召回率和调和平均 |
| 无目标图片误报率 | 至少有一次目标误报的确认无目标图片数／确认无目标图片总数 |

TP 是一对一匹配 GT 的预测；FP 是未匹配预测（含重复框）；FN 是未匹配目标 GT。AP 使用低分候选，不随当前分析置信度变化；P／R／F1 和误报率随工作点更新。无目标 GT 时 Recall／AP 为 N/A，无负样本时误报率为 N/A。

完整完成且超过一张图片的整个集合才显示主 AP。单图、子集和中断明确标记范围，主 AP 为 N/A；导出的描述性 `partial_metrics` 不能当作完整集合成绩。Train 观察拟合，Test 用于配置固定后的验证。

### 比较阈值，依次查看全部错图

默认扫描 0.05～0.95、步长 0.01，共 91 点。点击曲线／表格或调整「当前阈值」，同步更新指标和错例；非扫描点吸附到最近工作点，不重复推理。

「查看错例」进入预览、选择「全部错例」并定位首张。界面显示「错图 N／已评估 M／集合 K」与浏览序号，用「上一张」「下一张」依次查看。含 FP 或 FN（包括负图误报）的图计一次，一图多处错误仍只计一张，框数不等于错图数。子集与中断仅统计已完成项；零错显示零与空结果，缓存损坏则说明统计不可用。

可选「全部图片／包含误检／包含漏检／无目标图片误报／全部错例」。改分析阈值后后台更新匹配和名单，期间暂禁导航；「全部图片」恢复队列，「返回评估」保留当前阈值、分析子页与浏览状态，继续选阈值。

完整 Val 可查看 F1 最大、最低 Precision 约束或最高误报率约束的推荐工作点；无可行点不自动放宽。浏览或查看推荐不改检测配置。明确点击「采用到检测」，才将报告的输入、预处理、NMS、设备、原始目标 ID 和选定置信度应用到工作台，供图片、视频或摄像头检测；原报告不变。

### 诊断图表、扩展指标与场景

评估区使用四个子页：默认「阈值调优」、能力诊断、场景分析、报告管理。进入评估时收起重复的大标题栏，返回图像预览或其他页面后恢复，保留更多空间给实际分析。阈值调优左侧显示曲线、右侧显示推荐策略与约束，下方阈值表可拖动调整高度；当前阈值、Precision／Recall／F1／误报率和选中行同页联动。点击「定位推荐点」只更新分析，曲线保留当前点和推荐点；AP 属于整份报告，放在能力诊断。场景表明确采用生成报告时的工作阈值，若希望改变匹配 IoU 或生成该工作点的新场景报告，请重新分析。

- AP75 与 AP–IoU 表示定位要求变严格后的能力；PR 曲线来自低分候选，不等于随置信度变化的 P／R 曲线。
- FPPI 是误报框数／所有已评估图片数；负图平均误报框数只除以确认无目标图片数。Wilson 95% 区间反映无目标图片误报率的样本不确定性。
- 正图整图漏检率指含目标 GT、却没有任何正确定位预测的图片比例；与目标级 Recall 不同。
- 目标定位矩阵使用目标级 TP／FP／FN，背景 TN 没有定义；图像存在性矩阵只判断是否出现所选类预测，不判断框定位正确，二者不能混用。
- 完整集合按全部、小目标、遮挡、模糊、无目标和无困难六组分析。困难组依赖已审核 metadata；未提供审核时显示未知，不自动猜测。无目标组由所选类 GT 判断。无困难组只包含已审核且无困难标记、非负图的样本。组不足两张、单图／子集／中断任务不发布整集主 AP，描述值另存；空组与无定义指标显示 N/A。
- 点击场景的错例入口，按该场景已完成名单筛选当前阈值错误图片，可连续前后浏览；不会把范围外或未完成图片当错误。

### 独立重新分析与论文输出

在「报告管理」调整分析置信度、GT 匹配 IoU、扫描起止与步长，再点「重新分析」。应用校验历史报告、GT、预测及逐图快照后后台创建独立报告，不加载模型、不读取当前图片和标签；原报告与原图不变。完整／子集／中断范围和来源关系随新报告保留。缓存损坏或扫描低于原候选下限时拒绝，不能从已丢失候选恢复结果。

输出默认 PNG／SVG／PDF 三格式、300 DPI，可选择格式和 72～1200 DPI。九类图包括 PR、P／R／F1–置信度、无目标误报率–置信度、AP–IoU、FROC、目标定位矩阵、图像存在性矩阵、场景对比与 TP／FP／FN–置信度；专用 CSV 提供 PR、AP、场景和负图误报表，`paper-row.tex` 可复制至论文表格。格式和 DPI 应用于新评估或新分析报告；「导出原始评估报告」仍逐字节复制来源，另记当前分析选择，不改写旧图。

「导入脚本评估报告」可选择 `model-evaluation/evaluate.py` 生成的完整结果目录，需要 `status.json`、`metrics.json`、`inputs_manifest.json` 和 `predictions.jsonl`。导入校验原始类别、GT、预测和来源，生成新的本地报告，不改源目录；推理参数记录不完整时仅供分析，禁止自动采用检测配置，后续重分析继续保留此限制。旧结果范围或候选下限不满足时会明确拒绝，不补造预测。

原模型或数据集移走后仍可完成数值重分析；回看叠加仍需原图存在、尺寸和哈希一致。模型、NMS、候选下限、最大框数或预处理改变会改变候选，需要重新评估，不能仅用历史快照重算。没有 TensorRT 后端、新训练入口或多模型自动实验队列。

### 保存与重新打开

评估保存至个人数据目录 `evaluations/<任务ID>/`，包括固定配置、模型／数据哈希、GT 与低分预测快照、逐图结果、阈值／错例 CSV、Markdown 报告及所选 PNG／SVG／PDF 诊断图表。在「运行记录」双击评估记录，或从模型库「查看评估 / 检测配置」重开。

历史数值使用当时快照，叠加需原图存在且哈希相符。原图移动、改变或缓存损坏时提示原因，不把旧预测画到新图。「导出原始评估报告」复制完整报告并记录当前分析选择；单图导出对应当前选图与分析阈值。

目前不提供训练、多类总体 mAP、分类／裁剪评估、NMS 二维扫描或无标注视频在线 AP。

<a id="全局模型与结构显示"></a>

## 5. 查看结构与 YOLO YAML

模型库选用后在后台解析并缓存。进入「模型显示」或切模式复用缓存；结构图看连接、层级树看包含关系、参数表看张量元信息。树与表支持搜索和详情。无法解析时显示说明，可重试。

**仅能恢复支持的 YOLO 架构字典时显示「YOLO YAML」；ONNX 和不支持的模型直接隐藏该选项。** YAML 采用 One Dark Pro 风格只读代码视图，提供行号、语法高亮、搜索、复制和「另存 YAML」。

内容来自文件实际保存的架构，展示 `nc`、缩放参数、可用 anchors、`backbone`、`head` 和 `[from, repeats, module, args]`。这是等价配置，不能恢复原始训练 YAML 的注释、排版或路径；缩放影响重复数／通道，不等于实际算子数。**架构 YAML 与数据集 YAML 用途不同，不能互相替代。**

查看结构不执行 `torch.load` 或前向来猜连接。PT 层级不代表完整 forward，参数表含权重、常量和缓冲，不等于可训练参数总量。ONNX 更适合完整运算图，非 ONNX 保留完整结构提示。另存仅接受新的 `.yaml`／`.yml`，拒绝覆盖已有文件、符号链接或源模型，不改推理配置。

<a id="转换模型"></a>

## 6. 转换模型

「模型转换」默认用全局模型，将受支持的完整 PT／兼容 TorchScript 导出为 ONNX 或 TorchScript，不还原 ONNX 为可训练 PT。

1. 核对来源，选格式与 32～4096 px、32 倍数的正方形尺寸；通道保留模型 C1／C3。
2. ONNX 选择 Opset 12（优先兼容 OpenCV）或 17；统一 CPU FP32、batch=1、固定输入、不含 NMS。
3. 选择可写目录和新文件名，默认个人目录 `converted-models/`；已有文件／同名符号链接拒绝覆盖。
4. 「开始转换」后看后台进度与日志，可取消。开始时固定来源，切模型不改正在执行的转换；原模型和已有文件保留。
5. 成功后打开输出目录，或明确「加入模型库」选用结果；完成本身不替换全局模型。用实际输入核对转换结果。

导出会检查 ONNX 并比较固定测试输入，不能据此保证任意算子、真实图片或不同后端均兼容。转换使用随包 CPU 环境，与工作台设备选择独立；未知动态控制流、自定义算子及训练功能不保证保留。

## 7. 颜色、设备与流式输入

### 彩色与灰度

预处理需与训练一致。常见 YOLO 为 RGB、`1/255`、均值 0。ONNX 可调缩放／均值；PT 使用框架预处理，不支持的手工配置会报错。分类以模型说明为准，界面暂不提供逐通道标准差。

灰度先转换亮度：C1 输入一份，C3 输入三份相同亮度，预览和 PNG 底图同步变灰。ONNX 灰度统一用灰度均值（原 R 均值）；G／B 均值与 RGB／BGR 切换不改变灰度值。单通道需选灰度，当前图像输入支持固定 1／3 通道。选灰度不会把彩色模型变为灰度训练模型。

### CPU 与 NVIDIA GPU

工作台可选自动、CPU 或 NVIDIA GPU，多卡可选编号。自动在 GPU 不可用时说明原因并用 CPU，显式 GPU 失败报错；以状态、日志和导出的实际设备为准。

首次在「更多」检查并「准备 GPU 支持」，需联网约 4～5 GB，建议预留至少 20 GB。依赖位于个人目录 `gpu-runtime/`，可取消，不修改显卡驱动；实际 CUDA 自检通过才发布环境。配置后可离线推理。TensorRT、AMD 与 Intel GPU 尚未支持。

CPU ONNX 使用 C++ OpenCV DNN，GPU ONNX 使用 C++ ONNX Runtime CUDA，PT／TorchScript 使用本地常驻 Python／PyTorch。界面为 C++17／Qt 6.8，Netron 结构显示用 CPU 环境，不受推理设备影响。

### 左右拼接与录像

单设备输出水平左右拼接的视频／摄像头可选完整、左目或右目，先裁切再预处理，奇数宽度右目多一列。预览、坐标、导出和录像对应所选画面，JSON 另记源帧尺寸。数据集和临时图片始终用完整图像；此选项不提供双目测距。

视频／摄像头推理中点击「开始录制」，再次点「结束录制」。停止、源结束或退出也会收尾，待保存完在「录制视频」播放、打开目录或导出。输出为标注 MJPEG `.avi` 和同名 JSON，仅含实际处理帧，无音频；摄像头按实际录制时长确定播放帧率。图片队列不录制。

## 8. 导出、个人数据与升级

「更多 → 导出结果」或 `Ctrl+E` 保存当前选图／帧的标注 PNG、JSON、CSV，零目标也可保存。JSON 记录原始 ID、模型、配置、实际设备、耗时、颜色、通道与坐标来源，评估单图另有 GT／匹配。

「自动保存每张图片的结果」逐张保存本次范围（包括临时项）；视频／摄像头在结束时保存最后一帧，连续视频需录像。旁边「打开保存文件夹」进入实际目录。运行记录保留最近 200 次摘要，不替代完整导出。

系统安装于 `/opt/VisionStudio`；个人设置、模型列表、历史、导出、录像、评估和 GPU 环境位于 `${XDG_DATA_HOME:-$HOME/.local/share}/vision-studio`，可用 `VISION_STUDIO_DATA_DIR` 指定其他目录。程序不自动上传输入与预测。

升级前结束任务与录像、导出临时结果并退出旧程序，再按同版 README 校验安装。个人设置和持久报告保留，卸载不自动删除个人资料。正式 DEB 包含 CPU／Netron runtime，源码运行需另备依赖；实际安装与验收状态以发行凭证为准。

## 快捷键与常见问题

| 快捷键／操作 | 作用 |
| --- | --- |
| Ctrl+O／Ctrl+M | 导入数据集／导入模型 |
| Ctrl+R／Esc | 开始／停止；悬浮设置打开时 Esc 优先关闭 |
| Ctrl+E | 导出当前结果 |
| 画布滚轮／拖动 | 缩放／平移 |
| 双击、F 或 0／1 | 适应画布／原始尺寸 |
| 点击框或目标表 | 定位预测 |

| 现象 | 检查方向 |
| --- | --- |
| 数据集不能评估 | 核对集合、标签完整性、映射和审核状态，先看行内提示 |
| 模型有结构但无 YOLO YAML | 该格式或文件无支持的架构字典，入口隐藏；ONNX 仍可看结构图 |
| 启动不恢复数据集 | 核对「更多」开关、上次是否完整导入及源路径是否有效 |
| 检测为空或框不对 | 核对任务、输出格式、尺寸、阈值、类别 ID 和训练预处理 |
| 显卡可见但推理失败 | 在「更多」检查 runtime 和 CUDA 自检；驱动支持 CUDA 不等于依赖就绪 |
| 摄像头／视频打不开 | 核对编号、占用、权限或本机编码支持；左右目仅适用于水平拼接 |
| 历史报告无法叠加 | 原图需存在且哈希一致；保留历史数值，不借用改变后的图片 |
