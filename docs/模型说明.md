# 内置模型说明

## V1.6 计算设备与 GPU 模型

工作台的「自动 · 优先 NVIDIA GPU」「CPU」「NVIDIA GPU」决定推理设备，模型库的全局模型选择规则保持一致。CPU ONNX 使用 OpenCV DNN 4.5.4；GPU ONNX 使用 C++ ONNX Runtime 1.23.2 CUDA；PT 的 Ultralytics、兼容 YOLOv5 与 TorchScript 路径使用相应 CPU／CUDA PyTorch 环境。

模型输入、颜色、左右目裁切和后处理约定在各设备上保持一致，GPU 不会改变单通道灰度或三通道复制规则。ONNX 仍要求本项目支持的 NCHW 单图输入和原始检测／分类输出；ORT 能执行更多算子并不意味着分割、姿态、带 NMS 输出等任意模型已受支持。少量不适合 CUDA 的 ONNX 运算可能由 ORT 的 CPU provider 执行；应以模型实际执行和时间为准。

GPU 环境固定 PyTorch `2.9.1+cu128`、Torchvision `0.24.1+cu128`、CUDA 12.8、cuDNN 9.10.2 和 ONNX Runtime 1.23.2。首次到「更多」准备，下载后存储于个人数据目录 `gpu-runtime/`；CPU 与 Netron 环境独立保留。自动模式无法使用 GPU 时报告原因并回退 CPU，显式 NVIDIA GPU 模式不会静默回退。设备选择、实际设备和回退说明由运行状态及结果导出记录，不能根据模型文件名判断设备。

推荐 Linux NVIDIA 驱动 ≥ 570.26；RTX 4060 的 Ada／计算能力 8.9 在 CUDA 12.8 与 cuDNN 9.10.2 的官方范围内。驱动、具体模型算子及显存共同决定兼容性；CUDA 显存不足时可选择 CPU 或减小模型／输入。TensorRT、AMD、Intel GPU 尚未提供。[CUDA 12.8 说明](https://docs.nvidia.com/cuda/archive/12.8.0/cuda-toolkit-release-notes/index.html)、[cuDNN 支持矩阵](https://docs.nvidia.com/deeplearning/cudnn/backend/v9.10.2/reference/support-matrix.html)、[ORT CUDA](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html)。

## 1.5.0 模型显示

「模型显示」通过内嵌 Qt WebEngine 与 Netron 9.3.1 查看当前模型。模型库中的选择全局生效，工作台检测和模型显示共用同一个模型；选择后在后台异步预加载结构，完成后进入页面直接显示缓存，不重复加载。Netron 能解析某种文件，并不代表该文件符合本应用的推理输入和输出约定。

结构图、层级树和参数表共用同一解析结果；切换模式不重新加载模型。可搜索并查看节点、模块或参数详情，实际字段以文件提供的信息为准。深色样式覆盖嵌套对象、张量和详情，避免局部浅色背景影响阅读。

结构图保留 Netron 内置查找；层级树搜索名称、类型与路径，并保留匹配项的祖先；参数表搜索路径、dtype、shape、元素数与备注。详情只使用可靠保存的类型、路径和张量元数据，不读取全部张量值、不统计运行时激活，也不将权重、常量和缓冲合计宣称为可训练参数总量。展示节点、条目与深度设有限额，超出时提示截断。

页面由随包 Python 在本机回环随机端口提供，模型不上传远程服务。结构显示不执行 `torch.load`，也不通过模型代码运行一次推理来生成图。ONNX 中已声明的节点与边表示运算图；普通 `.pt` 仅展示可以静态解析的模块包含关系、权重分组和参数，不补造 forward 连接。TorchScript 等文件也可能只提供部分静态结构，实际可显示内容取决于文件和 Netron 的解析能力。格式不识别、文件损坏或缺少可显示结构时，界面给出中文说明和重试入口；选择其他模型应返回模型库。

## 1.5.0 灰度 ONNX 输入约定

模型库与工作台提供彩色 / 灰度输入选项，默认彩色，兼容旧版的 3 通道配置。ONNX 后端从图像输入元数据识别 NCHW 通道数，仅接受固定 C=1 或 C=3；旧式导出中同时列为 graph inputs 的 initializer 权重不计入运行时图像输入。动态 C、C=4、多个运行时输入以及非四维图像输入会报告不支持。

彩色模式要求 C=3，继续按所选 RGB / BGR 通道顺序处理。灰度先进行 8 位亮度转换（约为 `0.299R + 0.587G + 0.114B`），C=1 输入一个通道，C=3 复制为三个相同通道。ONNX 灰度缩放使用 `(灰度值 - meanR) × scale`，三通道灰度也统一减去同一均值，不使用 meanG / meanB。检测 letterbox 的原始补边值仍为 114，分类直接缩放到正方形；灰度预览和 PNG 标注底图显示实际灰度，尺寸及坐标空间保持所选画面。

将图像输入改为灰度必须与训练预处理一致。随附 YOLOv5n / YOLOv8n 是 COCO 彩色模型，默认示例保留彩色配置；选择灰度输入可以运行，但识别表现可能变化。单通道 ONNX 模型应选择灰度；应用不会在彩色模式下自动降为单通道。

## 单设备左右拼接画面与模型输入

摄像头或视频的完整 / 左目 / 右目选择在模型预处理之前执行。完整画面不裁切；左右目按源帧宽度中点切分，奇数宽度时右目保留多出的最后一列。所选眼图随后进行灰度转换、resize / letterbox 或模型原生预处理。检测坐标映射回所选眼图，原始拼接帧尺寸另行保存。图片输入保持完整。

此模式使用设备默认捕获分辨率；每眼实际图像宽高不等于模型固定输入尺寸。应继续填写模型要求的尺寸，应用负责裁切后的缩放和坐标映射。

## 灰度 .pt 输入约定

现代 Ultralytics、随附框架兼容的 YOLOv5 和标准检测 / 分类 TorchScript 支持固定 1 / 3 通道灰度输入。模型通道数依据实际输入层确定；YOLOv5 Focus 的首个卷积包含空间拼接产生的四倍内部通道，应用据此还原外部通道数。TorchScript 使用归档内 `config.txt` JSON 对象中的 `input_channels` 或四维 `shape` 元数据，并与能可靠识别的输入卷积约束核对；无法识别时需补充通道元数据，冲突或非 1 / 3 通道会拒绝载入。

`.pt` 灰度检测的输入仍采用 8 位亮度转换、114 补边与 `1 / 255`，检测输入尺寸须为 32 的倍数。现代灰度检测通过 BCHW 张量保留单通道，并将检测坐标准确还原到所选原图；灰度分类使用 Ultralytics 分类图像变换，明确设定所有通道 `mean=0`、`std=1`，再保留模型需要的通道。`.pt` 预处理维持零手工均值，ONNX 的 `meanR` / `scale` 自定义选项不适用于它。彩色模式仍要求三通道；灰度预览与 PNG 标注底图使用灰度；切回彩色恢复原色并清除旧检测，需重新运行。

## 静态转换与验证

转换于 2026-10-04 执行，使用 `onnx 1.17.0`、`onnxsim 0.4.36`，数值验证使用 `onnxruntime 1.28.0` 与 `numpy 2.4.6`。执行了 ONNX Simplifier 的三次检查，再以确定性输入比较原始与转换后模型的四个输出，本次数值比较最大绝对误差为 **0**。本机 C++ / OpenCV 4.5.4 对示例图片执行真实推理，检出 4 个 person 和 1 个 bus。

可使用 `scripts/prepare_bundled_model.py` 在具有上述依赖的独立 Python 环境中重现静态转换：

```bash
python scripts/prepare_bundled_model.py \
  models/source/yolov5n-v6.0-dynamic.onnx \
  models/yolov5n-rebuilt.onnx --size 640
```

机器可读来源记录保存在 `models/MODEL-PROVENANCE.json`。对于 ONNX 后端，Python 仅用于模型资源准备，ONNX 推理、导出和核心自动测试均由 C++ 完成。应用的内置 ONNX 模型固定为 640 输入，运行时应保留这个尺寸。

## 使用自己的模型

应用支持用户自行导入 ONNX 或受支持的完整 `.pt` 检查点。ONNX 兼容性取决于实际算子、输入预处理和输出格式，不能仅由 `.onnx` 文件后缀判断。模型载入和 forward 错误会由界面报告。

检测模型应导出中心坐标、宽高以及类别分数的原始张量，使用应用端阈值过滤和按类别 NMS。自定义标签文件每行一个名称，顺序与模型类别 ID 对应；数量必须匹配输出。建议使用 FP32、batch=1、固定正方形输入、不包含 NMS 的导出。
