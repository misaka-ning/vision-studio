# 内置模型说明

## YOLOv8n .pt 示例

直接 `.pt` 示例使用 [Ultralytics 官方 assets v8.3.0 发布](https://github.com/ultralytics/assets/releases/tag/v8.3.0)中的 [yolov8n.pt](https://github.com/ultralytics/assets/releases/download/v8.3.0/yolov8n.pt)，对应 [YOLOv8 检测模型](https://docs.ultralytics.com/models/yolov8)。检查点在本地 PyTorch / Ultralytics 后端载入，使用 CPU 推理，自动读取 COCO 80 类名称。

| 项目 | 资源信息 |
| --- | --- |
| 路径 | `models/yolov8n.pt` |
| 格式 | 完整 PyTorch / Ultralytics 检查点 |
| 大小 | 6,549,796 字节，约 6.25 MiB |
| SHA-256 | `f59b3d833e2ff32e194b5bb8e08d211dc7c5bdf144b90d2c8412c47ccfc83b36` |
| 任务 | COCO 80 类目标检测 |
| 后端 | 本地 CPU PyTorch，由 Qt 工作线程管理常驻 Python 进程 |
| 处理 | 原生 Ultralytics 图像预处理、置信度过滤、按类别 NMS |

来源记录保存在 `models/yolov8n.provenance.json`。Ultralytics 的官方说明列出 [AGPL-3.0 与 Enterprise 授权](https://docs.ultralytics.com/models/yolov8#citations-and-acknowledgments)；本项目保留下载来源与检查点原始文件，授权文本保存在 `models/Ultralytics-LICENSE.txt`。

检查点载入可能通过 pickle 执行 Python 代码，应使用自己训练或来源可信的 `.pt`。文件扩展名本身不能确定模型兼容性。只有 `state_dict` 的文件缺少架构信息；自定义网络类需要相应项目代码。

独立 CPU runtime 的实际版本和依赖记录见 `runtime-info.json`、`requirements-pt.txt` 与 `requirements-pt.lock.txt`。Python 只承担 `.pt` 后端和可选模型准备工具；ONNX 仍由 C++ / OpenCV 执行。

## YOLOv5n .pt 示例

旧版 PyTorch 示例取自 [Ultralytics YOLOv5 v6.0 官方发布](https://github.com/ultralytics/yolov5/releases/tag/v6.0)，文件为 [yolov5n.pt](https://github.com/ultralytics/yolov5/releases/download/v6.0/yolov5n.pt)。`models/yolov5n.pt` 大小为 3,952,441 字节，SHA-256 为：

```text
649e089f59b78ac021025de035b2d9c45dc26e544ea252955d0ffcefc1099e2f
```

应用保留 v6.0 官方检查点，使用随附 `vendor/yolov5` v7.0 网络类作为兼容框架，再在 PyTorch CPU 上执行。检查点来源项目与兼容框架均使用 GPL-3.0；[v6.0 模型授权](https://github.com/ultralytics/yolov5/blob/v6.0/LICENSE)保存在 `models/YOLOv5-LICENSE.txt`，[v7.0 框架授权](https://github.com/ultralytics/yolov5/blob/v7.0/LICENSE)保存在 `vendor/yolov5/LICENSE`。资源来源记录为 `models/yolov5n-pt.provenance.json`。使用兼容标准模块的自训练检查点可载入；自定义模块仍需要训练项目的对应类。

带 `config.txt` 任务和类别元数据的 TorchScript `.pt` 也可载入。检测输出需为 `[1,N,5+C]` 或 `[1,4+C,N]`，分类输出需包含单图类别值。TorchScript 分类输入使用 Ultralytics `classify_transforms` 与 PIL RGB，模型需与此标准分类预处理匹配。应用不会通过裸 `state_dict` 推断未知架构。

## YOLOv5n 示例

内置模型取自 [Ultralytics YOLOv5 v6.0 官方发布](https://github.com/ultralytics/yolov5/releases/tag/v6.0)，原始文件为 [yolov5n.onnx](https://github.com/ultralytics/yolov5/releases/download/v6.0/yolov5n.onnx)。官方文件声明动态输入，包含本机 OpenCV 4.5.4 不支持的动态 Range / Expand 组合；本项目使用 ONNX Simplifier 固定输入为 640 × 640 并折叠动态形状计算，保留原始预训练权重。官方原文件保存在 `models/source/yolov5n-v6.0-dynamic.onnx`，应用运行的兼容文件为 `models/yolov5n.onnx`。

示例图片为同一版本中的 [bus.jpg](https://github.com/ultralytics/yolov5/blob/v6.0/data/images/bus.jpg)。应用在本机 OpenCV DNN 执行真实模型，不以示范数据替代推理。

| 项目 | 实际资源信息 |
| --- | --- |
| 模型路径 | `models/yolov5n.onnx` |
| 模型大小 | 约 7.6 MiB（兼容静态版本） |
| ONNX IR / opset | IR 7 / opset 14 |
| 输入 | `images`，FP32，NCHW，固定 `[1, 3, 640, 640]` |
| 主要检测输出 | `output`，640 输入时为 `[1, 25200, 85]`；含 80 类分数与 objectness |
| 辅助输出 | `350` 为 `[1,3,80,80,85]`、`498` 为 `[1,3,40,40,85]`、`646` 为 `[1,3,20,20,85]`，由应用跳过 |
| 预处理 | RGB，`1 / 255` 缩放，零均值，letterbox 补边值 114 |
| 后处理 | 置信度 0.25，按类别 NMS IoU 0.45，原图坐标裁剪 |
| 标签 | COCO 80 类，按官方类别 ID 顺序 |

## 静态转换与验证

转换于 2026-10-04 执行，使用 `onnx 1.17.0`、`onnxsim 0.4.36`，数值验证使用 `onnxruntime 1.28.0` 与 `numpy 2.4.6`。执行了 ONNX Simplifier 的三次检查，再以确定性输入比较原始与转换后模型的四个输出，本次数值比较最大绝对误差为 **0**。本机 C++ / OpenCV 4.5.4 对示例图片执行真实推理，检出 4 个 person 和 1 个 bus。

可使用 `scripts/prepare_bundled_model.py` 在具有上述依赖的独立 Python 环境中重现静态转换：

```bash
python scripts/prepare_bundled_model.py \
  models/source/yolov5n-v6.0-dynamic.onnx \
  models/yolov5n-rebuilt.onnx --size 640
```

机器可读来源记录保存在 `models/MODEL-PROVENANCE.json`。对于 ONNX 后端，Python 仅用于模型资源准备，ONNX 推理、导出和核心自动测试均由 C++ 完成。应用的内置 ONNX 模型固定为 640 输入，运行时应保留这个尺寸。

## 使用自己的模型

应用支持用户自行导入 ONNX 或受支持的完整 `.pt` 检查点。ONNX 兼容性取决于实际算子、输入预处理和输出格式，不能仅由 `.onnx` 文件后缀判断。模型载入和 forward 错误会由界面报告。

检测模型应导出中心坐标、宽高以及类别分数的原始张量，使用应用端阈值过滤和按类别 NMS。自定义标签文件每行一个名称，顺序与模型类别 ID 对应；数量必须匹配输出。建议使用 FP32、batch=1、固定正方形输入、不包含 NMS 的导出。
