# 对应源码与重建

本次交付的两个主文件为 DEB 与 `vision-studio-2.0.0-beta.2-complete-source.tar.xz`，由 `SHA256SUMS` 校验。完整源码包包含应用源码归档 `vision-studio-2.0.0-beta.2-sources.tar.xz`、`sources/` 下的原始上游源码、`SOURCE-INVENTORY.json` 及校验内部文件的 `SOURCE-SHA256SUMS`。新编写的代码按 AGPL-3.0-only 发布，维护者为 misaka_ning <1468549029@qq.com>。源码清单记录各份上游源码的来源、版本和哈希；模型的独立来源及哈希记录在 `models/` 的 provenance 文件中。

## 源码内容

应用源码归档包含 `src/`、`tests/`、`scripts/`、`packaging/`、CMake 工程、UI 资源、文档、示例图片、模型和原始 ONNX 文件，以及完整的 `vendor/yolov5` 网络兼容源码。不包含本机缓存、用户设置、运行历史或 Python 虚拟环境。随归档提供的 `packaging/build_deb.py` 记录实际文件复制、共享库依赖检查、RUNPATH 设置和运行时库替换操作。

`sources/` 保留下列原始归档，而不是仅给出网页链接：

| 组件 | 对应源码 |
| --- | --- |
| Qt 6.8.3 运行库、XCB / Wayland / 图片插件 | qtbase、qtsvg、qtwayland、qtimageformats 原始源码归档 |
| Qt WebEngine 及 Qml / Quick / WebChannel / Positioning 依赖 | qtdeclarative、qtwebchannel、qtpositioning、qtwebengine 原始源码归档；后者包含对应 Chromium 源码 |
| Netron 9.3.1 Python / JS 前端 | 官方 v9.3.1 tag 完整源码 `netron-9.3.1-source.tar.gz`；原始 MIT 与前端 Dagre / Graphlib 通知随应用源码保存 |
| Ultralytics 8.4.173 / THOP 2.2.2 | 官方 PyPI 源码发行包 |

Qt 原始源码包含其嵌入的第三方代码及许可证。实际 SDK 的 SPDX 文档与本次 QtImageFormats 构建产生的原始 SPDX 文档均已保留；完整上游源码通知还提取到了 `licenses/qt/source-notices/`。QtWebEngine SDK 的 SPDX 不逐项涵盖全部 Chromium 组件，因此另外保存了完整原始源码、`LICENSE.Chromium`、Chromium 各组件的 LICENSE / COPYING / NOTICE 与 `README.chromium` 许可信息。QtImageFormats 的构建 SPDX 有源码归档环境产生的 `+HEAD+dirty` 标记；该文件按原样保留，模块版本由原始 6.8.3 归档与其已核验哈希确定。

Qt 的官方许可说明要求提供对应源码并允许用户替换或重新链接 Qt，单纯提供上游网址不能代替所需交付。因此本次将原始 Qt 源码与二进制一起交付。[Qt LGPL 说明](https://www.qt.io/faq/qt-open-source-licensing)

## 构建应用

在 Ubuntu 22.04 amd64 上准备 C++17 编译器、CMake ≥ 3.21、Qt 6.8.3 Core / Gui / Widgets / Svg / Network / WebChannel / WebEngineWidgets / Test 开发文件，以及系统 OpenCV 4.5.4 开发文件。Qt WebEngine 的间接依赖包括 Qml / Quick / QuickWidgets / Positioning；SDK 还须带 `libexec/QtWebEngineProcess`、`resources/` 与 `translations/qtwebengine_locales/`。Qt SDK 可以放在其他目录；通过 `CMAKE_PREFIX_PATH` 指定。

```bash
tar -xf vision-studio-2.0.0-beta.2-sources.tar.xz
cd vision-studio-2.0.0-beta.2
cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON \
  -DVISION_RESOURCE_FALLBACK=/opt/VisionStudio \
  -DCMAKE_PREFIX_PATH="$HOME/Qt/6.8.3/gcc_64"
cmake --build build/release -j
```

重新准备发行用独立环境时，使用 Ubuntu 的 Python 3.10。`requirements-release.lock.txt` 是根据发行环境实际元数据生成的 57 项版本清单，包含 Netron 9.3.1；安装时禁止额外依赖解析，以保留发行用无 GUI OpenCV wheel。

```bash
python3.10 -m venv build/release-runtime
build/release-runtime/bin/python -m pip install --upgrade pip
build/release-runtime/bin/python -m pip install --no-deps \
  --extra-index-url https://download.pytorch.org/whl/cpu \
  -r docs/release/requirements-release.lock.txt
VISION_STUDIO_PYTHON="$PWD/build/release-runtime/bin/python" \
  ctest --test-dir build/release --output-on-failure
```

依赖初次准备需要网络；依赖准备后，本地推理和模型显示可离线执行。`scripts/setup_pt.sh` 是便携版环境准备脚本；正式发行重建应使用 `docs/release/requirements-release.lock.txt`，以保留本次实际捆绑的无 GUI OpenCV 与 Netron 版本。

Netron 官方 PyPI 此版本只提供 wheel，因此源码包另带官方 v9.3.1 tag 的完整 Python / JS 源码。若需要从该源码重建安装包，在解压后的 Netron 根目录执行：

```bash
python3.10 package.py build version
/应用环境绝对路径/bin/python -m pip install --no-deps ./dist/pypi
```

上游命令复制前端文件并按 tag 元数据写入 9.3.1 版本信息。运行时不需要 Electron 或 Node 开发依赖；Node 在下文重建 QtWebEngine 时属于构建工具。

## 可选 GPU 环境与源码范围

正式 DEB 继续包含完整离线 CPU／Netron 环境；GPU CUDA wheel 不嵌入 DEB 或完整源码包。应用源码包含 `gpu_setup.py`、`gpu_probe.py`、`setup_gpu.sh`、完整 `requirements-gpu*.txt` 版本／官方 SHA256 锁和 C++ ONNX Runtime API 接口。GPU 环境使用 PyTorch `2.9.1+cu128`、Torchvision `0.24.1+cu128`、ONNX Runtime 1.23.2；运行库从官方源下载至用户目录。

```bash
./scripts/setup_gpu.sh
/usr/bin/python3.10 scripts/gpu_probe.py
```

系统 Python 3.10 需要 venv 模块（Ubuntu `python3.10-venv`）；GPU 初次准备需要网络、已有 NVIDIA 驱动及至少 20 GB 空间。`--runtime-dir` 指定专用用户目录；成功自检后原子发布 ready.json，取消／失败保留旧环境。不修改 CPU runtime 或 GPU 驱动。下载库只保留 wheel 原字节，不做 strip 或 DEB 的 GNU 库替换。

GPU 环境内保存实际发行版／许可清单和原始 wheel 通知。NVIDIA 专有组件保留自身许可，不能把它们当作本应用 AGPL 对应源码；本项目发行包不再分发这些可选 GPU 库。其他随包组件继续依下文提供完整对应源码与重建材料。

## 重建 Qt 与允许替换

可从八份 Qt 原始归档重建共享库。先构建 qtbase，再使用其安装前缀的 `bin/qt-configure-module` 配置 qtsvg、qtwayland、qtimageformats、qtdeclarative、qtwebchannel、qtpositioning，最后配置 qtwebengine。QtWebChannel 与 QtWebEngine 要求此前的 Qml / Quick 依赖已安装。操作系统开发依赖与启用特性应覆盖 XCB、Wayland、SVG、图像插件和 WebEngine。上游配置、CMake 文件和嵌入源码均保留在归档中。有关配置参数见 [Qt 构建说明](https://doc.qt.io/qt-6.8/build-sources.html)。下列 Qt 命令在包含 `sources/` 的发行目录或完整源码包解压根目录执行；若当前在 `vision-studio-2.0.0-beta.2` 应用源码目录，先返回上一级。

```bash
tar -xf sources/qtbase-everywhere-src-6.8.3.tar.xz
mkdir qtbase-build
cd qtbase-build
../qtbase-everywhere-src-6.8.3/configure -prefix "$HOME/qt-6.8.3-modified" \
  -release -opensource -confirm-license -nomake examples -nomake tests
cmake --build . -j
cmake --install .
```

每个额外模块解压后，在独立构建目录执行 `"$HOME/qt-6.8.3-modified/bin/qt-configure-module" /模块源码绝对路径`，然后执行 `cmake --build . -j` 与 `cmake --install .`。

QtWebEngine / Chromium 的构建比应用本身需要更多工具，包括支持 C++20 的编译器、Node、Python 与 html5lib、Ninja、gperf、bison、flex，以及 Linux 的 pkg-config、NSS 和图形开发依赖。版本要求以配套 6.8.3 源码配置检查为准；[Qt WebEngine 平台说明](https://doc.qt.io/qt-6.8/qtwebengine-platform-notes.html)列出各平台要求。官方 6.8 文档会随 LTS 补丁更新，不能用网页当前版本号替代本次 6.8.3 归档的身份。

发行程序通过共享库动态链接 Qt；允许用户修改 Qt、替换 Qt 库及插件，或重新构建应用并链接修改后的 Qt。发行版没有禁止为调试库修改而进行的逆向工程，也不要求签名才能执行修改版本。兼容的替换前缀应包含 `lib/libQt6Core.so.6`、`plugins/platforms/`、`libexec/QtWebEngineProcess`、WebEngine 的 `resources/` 及 `translations/qtwebengine_locales/`。

```bash
VISION_STUDIO_QT_HOME="$HOME/qt-6.8.3-modified" vision-studio
```

启动器将该前缀的 `lib` 放在 `LD_LIBRARY_PATH` 前面，并使用其 Qt 插件、WebEngine 辅助进程、资源与语言目录。应用使用 RUNPATH，使这一覆盖能够生效。Qt ABI、启用特性和依赖须与应用要求兼容；若有不兼容修改，可使用完整应用源码重新构建。

## 发行运行时的实际变更

Python wheel 的 `.py` 文件、许可证和第三方 NOTICE 保留。为使用 Ubuntu 的系统 GNU 运行库，`packaging/build_deb.py` 在**暂存副本**中核验需要的 ABI / 符号版本，再将 NumPy 等本机扩展的 GNU 库依赖改为系统 `libgfortran.so.5`、`libquadmath.so.0` 和 `libgomp.so.1`，删除 wheel 内的对应副本，并据实际 ELF 依赖生成 Debian Depends。

OpenCV wheel 的旧 LP64 OpenBLAS 依赖 gfortran3，不能直接改为 gfortran5。本次将其 BLAS / LAPACK 入口改为 Ubuntu `libblas.so.3` 与 `liblapack.so.3`，核验入口符号后删除其旧 OpenBLAS。NumPy 所用独立 ILP64 OpenBLAS 保留。脚本是这些变更的完整记录；不会修改原始虚拟环境或系统 Qt SDK。系统 GNU 运行库通过系统软件包提供，其对应源码由 Ubuntu 软件包仓库提供。

FFmpeg 来自 OpenCV 无 GUI wheel，实际 `av_version_info()` 返回 **5.1.6**，实际库报告 LGPL 2.1 或以后版本。它的源码、原始 wheel 构建 Dockerfile 与实际 `avutil_configuration()` 均随本次交付保存。FFmpeg 源码和 wheel 中的 FFmpeg 库均未修改。Python wheel 保留原 RUNPATH；上述 BLAS / GNU 变更只重绑定指定库的 DT_NEEDED。应用与 Qt 的 RUNPATH 调整由打包脚本记录。[FFmpeg 许可及源码说明](https://ffmpeg.org/legal.html)

## 生成并检查 DEB

完整参数和系统打包依赖见 `packaging/README.md`。使用源码中的 `packaging/build_deb.py`，指定已构建应用、Qt SDK、额外 QtImageFormats 插件目录和发行用 runtime。脚本创建全新暂存目录，推导系统依赖并生成 `vision-studio_2.0.0-beta.2-1_amd64.deb`。`packaging/verify_deb.py` 在普通用户环境解包检查版权、源码校验、运行库、模型、桌面入口、路径及真实推理；`packaging/verify_install_namespace.py` 在隔离命名空间内执行安装、普通用户运行及卸载检查。

2.0.0-beta.2 修复批量检测后的结果回看，保留 Beta.1 的 Fluent 界面；CPU／GPU 推理、Qt／Netron 交付与依赖版本沿用 1.6.0，并复用已有 15 份原始上游源码与构建输入；可选 GPU 用户环境另有完整版本与 SHA256 锁，不改变 CPU 归档。新发行目录为 `output/releases/2.0.0-beta.2/`；可将已核验的原始归档硬链接到其 `sources/`，并单独复制 `DOWNLOAD-PROVENANCE.json`。硬链接仅用于复用不可变的上游文件，不能修改其中内容；旧版本的归档、DEB 与校验清单不覆盖。应用源码、清单和外层完整源码包需重新生成，使其包含本次代码和文档。

冻结代码前可先执行清单检查；此命令只核验上游文件并写入当前版本的清单与发行依赖锁，不生成源码归档：

```bash
python3 docs/release/build_source_archive.py --source-root . \
  --release-directory output/releases/2.0.0-beta.2 --inventory-only
```

本版构建与功能验收完成后，先生成正式 DEB，再运行下文的源码归档命令。最后在发行目录执行 `sha256sum -c SHA256SUMS` 和 `sha256sum -c SOURCE-SHA256SUMS`，并用 `verify_deb.py --source-dir` 核对配套来源。源码打包时会嵌入原始上游归档，公开清单只包含 DEB 和完整源码包；内部清单覆盖应用源码与各份上游材料。

许可证快照可重新生成：

```bash
python3 docs/release/collect_licenses.py --runtime build/release-runtime \
  --qt-sdk "$HOME/Qt/6.8.3/gcc_64" --qt-sources output/releases/2.0.0-beta.2/sources \
  --qt-imageformats-prefix build/qt-imageformats-prefix \
  --netron-source output/releases/2.0.0-beta.2/sources/netron-9.3.1-source.tar.gz
python3 docs/release/build_source_archive.py --source-root . \
  --release-directory output/releases/2.0.0-beta.2
```

这些步骤用于重建功能与打包内容，不承诺在不同编译器、容器或操作系统开发环境下产生逐字节相同的二进制。每份已交付文件的身份以该次发行 `SHA256SUMS` 为准。许可完整条款以随包原文为准；本说明记录了交付与重建方法。
